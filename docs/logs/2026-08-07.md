- 理由: `auth.getUser()` は毎回 `GET /auth/v1/user` へのHTTP往復でローカルキャッシュがない。
  `/calendar` 1リクエストで4回(proxy / layout / page / materialize)直列に往復しており、
  RSCではlayoutのawaitが解決するまでchildrenが始まらないため、そのままTTFBに積み上がっていた
- 設計上の判断:
  - **React `cache()` 単独にしなかった**。前日の実測どおり `cache()` はリクエストコンテキスト外で
    素通しするため、「1リクエストで1回」を vitest で固定できない。WeakMap なら RSC・Server Action・
    Route Handler・テストのすべてで同じ挙動になり、回帰防止テストが書ける
  - **`getSessionUser` を `lib/supabase/server.ts` に置かなかった**。同ファイルは `next/headers` を
    importしており、そこに置くと `lib/` のサービス層全体がNextのリクエストAPIに依存してしまう。
    `next/headers` に依存しない別モジュールに分離した
  - 既存のDI(テストがモッククライアントを注入する設計)を維持するため、`getSessionUser` は
    引数で client を受け取る形にした
