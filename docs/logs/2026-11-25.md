## サマリーのページテスト3件が早朝に失敗する不具合(G-90 由来・R-1 の再発)

- 発見: 2026-11-26 07:55(JST)に docs のコミットを試みたところ、pre-commit の単体テストが2件失敗した(`page-counts.test.tsx` S3、`page.test.tsx` P5-8 S7)
- 原因: G-90(PR #118)で、サマリーが「開始が現在より後で未着手の予定」を途中経過の集計から除くようにした。
  `page` / `page-counts` / `page-range` の3テストは `startOfDay(new Date())` と実時刻で今日の予定(10:00〜16:00)を組み立てており、
  早朝(予定の開始より前)に実行すると予定が「これから」扱いになって期待と食い違う。G-90 は23時台に実装・検証したため、全予定が過去になっていて気づけなかった
- なぜ見逃したか: CLAUDE.md R-1 の「現在時刻を扱うテストは時刻まで固定する」を、G-90 の新規ロジックが既存の時刻非固定のテストに波及する点で見落とした。
  G-90 では新規テストの時刻は固定したが、**既存テストのうち、変更した関数を通る画面テストの時刻依存を洗わなかった**
- 対応: 3ファイルに、モジュール評価より前(`vi.hoisted`)で 2026-11-24 23:30 に固定する処理を追加した。夜23:30なら日中の予定がすべて経過した扱いで、従来の期待をそのまま保てる。
  UTC・UTC+14・JST で合格を確認
- 再発防止(提案・ユーザー判断待ち): 時刻に応じて結果が変わる**ロジックを変更したときは、そのロジックを通る既存テストを、実行時刻を変えて(早朝・深夜)確認する**
  ことを R-1 に追記する。CLAUDE.md はユーザーの文書のため、私は変更していない
