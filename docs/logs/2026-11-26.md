## CI の `db:types` ステップに再試行を追加(G-114 の追補)

- 事象: PR #127 の CI で、integration ジョブの「Verify generated database types are up to date」が失敗した。
  原因は型のずれではなく、`supabase gen types` が pg-meta の Docker イメージを `public.ecr.aws` から取得する際の
  `docker: Error response from daemon: error from registry: Data limit exceeded`(取得量制限)。失敗ジョブの再実行で合格した
- 対応: 型の生成(`npm run db:types`)だけを最大3回、30秒・60秒の待ちで再試行するようにした。型のずれの判定(`git diff --exit-code`)は再試行しない
- 経緯: G-114 の独立レビュー(R3)で、「pull に失敗する場合は再試行を入れる」と指摘されていた。そのときは確証がなく変更しなかったが、実際に起きた
- 検証: 再試行の分岐そのものは、CI で取得制限が起きたときにしか動かない。構文は actionlint(`check` ジョブ)と、正常系は CI の実行で確認する
