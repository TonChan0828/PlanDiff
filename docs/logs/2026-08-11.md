## 10:45 P8-1(日付またぎの自動反映)の調査と実装

- やったこと:
  - ユーザー報告「日にちをまたぐと自動で次の日の表示にしたい」を調査し、**原因が2つ重なっている**ことを特定
    1. **時刻の再レンダートリガーが存在しない**。`components/calendar-view.tsx` は「今日」も「現在時刻」も
       レンダー中に素の `new Date()` を評価するだけで、state にも外部ストアにも載っていない。
       アプリ内で `setInterval` を持つのは `lib/timer/use-now-seconds.ts` の1箇所のみで、これは
       `RunningTimerBar` / `RunningTimerHero` の内部で購読されるため親の `CalendarView` は再レンダーされない。
       `visibilitychange` / `focus` / `pageshow` のリスナは**全画面でゼロ件**だった
    2. **URL が日付を固定する**。`buildCalendarPath` が常に `?view=day&date=YYYY-MM-DD` を生成するため、
       「今日」ボタンや週ストリップのタップでも日付がURLに焼き込まれ、(1) を直しても切り替わらない
  - 仕様書 `docs/specs/P8-1_日付またぎの自動反映.md` を作成し、ユーザー承認を取得
  - 実装(TDD: Red → Green)
    - `lib/time/use-now-minute.ts` 新設。分単位の現在時刻を配信する**モジュールスコープの共有ストア**。
      **分境界にアラインした `setTimeout` 連鎖**で駆動し(固定間隔だと0時の検知が最大60秒遅れる)、
      `visibilitychange` / `focus` / `pageshow` でも再計算する
    - `lib/calendar/view-date.ts` の `buildCalendarPath` に `today` 引数を追加。
      **「URLの `date` は今日以外を見ているときだけ持つ」不変条件**にした
    - `components/calendar-view.tsx` をこのストアに載せ替え。ローカルの `useHydrated` は
      `useNowMinuteMs() !== null` と役割が重複するため削除。日付キーが変わったときだけ
      `router.refresh()` を1回呼ぶ effect を追加(props のイベント・実績が前日基準のままになるため)
- 理由:
  - 追従条件は「今日を見ているときだけ」(ユーザー選択)。過去日を開いて作業中に表示を奪われないため
  - 不変条件(2)を入れると「今日を見ている」= `date` パラメータなし、と表現できるので、
    **前回の「今日」を保持して比較する ref が不要**になり実装が単純になる
  - 現在時刻ラインなど「時刻」の追従も同時に入れた(ユーザー選択)。同じ原因で止まっていたため
- 途中で見つけた実装の穴(テストで検出・修正):
  - ストアがモジュールスコープのため、**購読が途切れている間 `snapshot` が古いまま止まる**。
    マウント直後の初回レンダーだけ古い値を返し、購読開始後の訂正が「時刻が変わった」ように見えて
    `router.refresh()` が誤発火していた(S18 が Red)。`getSnapshot` を
    「購読者0のときは現在時刻から作り直す」形にして解消
- 結果:

  - `npm run check` 合格(EXIT=0)
  - R-1: `TZ=UTC` / `TZ=Pacific/Kiritimati`(UTC+14)の両方で対象3ファイル46件合格
  - 既存テスト2件を**仕様変更に伴い更新**(無効化ではない): `calendar-view.test.tsx` の
    S8「ビュー切替」と S9「今日ボタン」の遷移先が `?...&date=<今日>` → `?view=...`(date なし)に変わる
  - 手動確認(Playwright + `page.clock`、375px):
    - `/calendar` を開くとURLに `date` が付かない。「今日」ボタンでも付かない(`?view=day`)
    - 「前へ」で `?view=day&date=2026-08-10` が付く
    - **23:59:30 に固定 → 60秒進めると `2026年8月11日(火)` → `2026年8月12日(水)` に自動追従**。

## 22:35 P8-2(計測画面の日付またぎ)の調査と実装

- やったこと:
  - 仕様書 `docs/specs/P8-2_計測画面の日付またぎ.md` を作成しユーザー承認を取得
  - 原因は P8-1 と同じ(時刻の再レンダートリガー不在)。`components/track-view.tsx` の `now` は
    ローカル定義の `useHydrated`(ハイドレーション完了時に1回だけ `new Date()` を評価)を使っており、
    それ以降更新されない。**`now` が前日のまま止まると、実際は当日になった実績が
    `groupEntriesByDay` の未来日除外ロジック(`day.getTime() > today.getTime()`)で
    誤って弾かれる**。「今の予定から開始」の進行中/当日候補判定も同様に古い日付のまま固定される
  - P8-1 との違い: `/track` は `dateParam` を持たず、サーバーは常に
    `computeSyncRange(new Date())` = 基準週の前後1週間(計3週間分)を取得しているため、
    日付が1日進んだ程度ではこの範囲を外れない。**`router.refresh()` は不要**で、
    クライアント側の `now` を更新するだけで直る(P8-1より単純)
  - 実装(TDD: Red → Green): `track-view.tsx` のローカル `useHydrated` を削除し、
    P8-1で新設した共有ストア `lib/time/use-now-minute.ts` の `useNowMinuteMs()` に置き換え
- 理由:
  - 同じ原因の別画面なので、P8-1 で作った共有ストアをそのまま再利用するのが最小の変更
- 結果:
  - 自動テスト **+3件(計696件)全合格**。R-1: `TZ=UTC` / `TZ=Pacific/Kiritimati` で対象ファイル確認済み
  - `npm run check` 合格(EXIT=0)
  - 手動確認(Playwright `page.clock`、375px ライト/ダーク):
    - 23:59:30 に開始時刻を跨ぐ予定(前日22:00〜0:02)は「進行中」表示のまま、
      0時をまたいで6分進めると終了時刻(0:02)を過ぎ「今の予定から開始」から消える
      (修正前は `now` が凍結され永久に「進行中」表示され続けるバグだった)
    - 0時直後(0:00:30)開始の予定は、0時をまたぐ前は候補に出ず、またいだ後に
      「今の予定から開始」の候補として現れる
    - 0時直後(0:00:30)開始の実績は、0時をまたぐ前は「未来日」として非表示、
      またいだ後に「今日」グループへ正しく現れることを確認(元のバグの再現・解消を実機確認)
    - 375px ライト/ダーク両方でレイアウト崩れなし、横スクロール 0px
- 未解決・次にやること:
  - PR作成とマージ
  - P8-3(サマリーの日付またぎ+TZ非対称の是正)が着手待ち
