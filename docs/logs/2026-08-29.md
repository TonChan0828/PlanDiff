## 22:00 柔らかさと色被りの解消(D-6 修正2)

- やったこと:
  - ユーザーから「もう少し柔らかい色味にしたい」「色被りが在って気になる」との指摘
  - 色相と彩度を数値化して原因を特定。**`--brand` と `--danger` の色相差が 23° しかなかった**。
    コーラルが `--brand` を占めたことで `--danger` も赤系に押し込まれ、カレンダー上で
    予定の薄塗り・実績・現在時刻ラインが**全て赤系**に見えていた
  - 2案を数値で比較:
    - 案A: コーラル据え置き・`--danger` を深いプラム(325°)へ → **AA全通過・S18 OK・色相差41°**
    - 案B: `--brand` をダスティブルー・コーラルを `--interrupt` へ → `--interrupt` と `--danger` が
      **20°に接近して問題が移動するだけ**。さらに S18(明度差)が 1.37:1 で不合格
  - 案Aを採用。全体の彩度を 35–75% → **23–31%** に落とし、`--ink` も純黒 `#141414` から
    柔らかい炭色 `#33302e` へ
  - S19(色相差 35°以上)・S20(彩度 40%以下)をテストに追加
- 理由:
  - **白文字とのAA(4.5:1)があるため明度は上げられない**。「柔らかくする」を
    「明るくする」で実現しようとすると必ずAAが崩れる。**彩度を下げる**のが唯一の道だった
  - 色被りは主観的な訴えだが、色相差という数値に落とせる。落とせるならテストにできる。
    S19 を入れたので、今後パレットを触って再び色が寄ったら落ちる
- 結果: `npm run check` 合格。**129ファイル / 835件 全合格**、ビルド成功
- 学び: **パレットの制約は「値」ではなく「関係」にある**。brand を変えるだけで
  danger との関係が壊れ、danger を柔らかくすると今度は現在時刻ラインの視認性が壊れる。
  S14(コントラスト)・S18(明度差)・S19(色相差)・S20(彩度)の4つで
  関係そのものを固定したので、次に誰が色を触っても壊れたら分かる
- 未解決・次にやること: 認証必須ページの375px確認は引き続き未実施
