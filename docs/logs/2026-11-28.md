## G-104 週表示の長時間実績の省略(Issue #104)

- やったこと: テストを先に書いて Red を確認 → `lib/calendar/long-entry.ts` と、`layoutDayEvents` の配置専用の範囲(`layoutStartAt` / `layoutEndAt`)を追加。元の `startAt` / `endAt` は書き換えない(ズレの計算・編集パネル・`title` がそのまま使うため)
  - 週表示だけで、列の割り当ての前に縮める(後半の時間帯の実績が全幅になることをテストで固定)。超過の斜線は省略ブロックの下端まで、続きの日の印には斜線を出さない
- **スクリーンショットで見つけた問題**: 超過の斜線は後から描くため、省略ブロック(ほぼ全体が超過)の文字に重なって読めなかった。数値のテストと E2E(文字がブロック内にある・画面内にある)は合格していた → 文字を前面に出し、ブロックと同じ色の下地を敷いた
- 結果: 単体・画面全件合格(UTC・UTC+14・America/Los_Angeles でも確認)、E2E 20件(375px)合格、修正後のスクリーンショットで目視
- G-104 レビュー(周1): major 2件・minor 3件
  - **R2(major)**: 仕様は「開始日の列にだけ2時間ぶん、続きの日は印」なのに、2時間が0時をまたぐと翌日にも本体を出していた。私の境界テストが、**仕様と違う動きを正しいものとして固定していた** → 本体は開始日だけ(0時で切る)にし、テストを仕様どおりに直した
  - **R1(major)**: 続きの日の印(約22px)では「前日から継続(省略)」の「省略」が切れて読めない → 印を45分ぶんの高さに。0時の直前に始まる本体は90分ぶんになるよう上に広げる(実際の時刻は不変)
  - 直したあとの E2E とスクリーンショットで、印が28px以上になったため**再計測ボタンが印の文字に重なる**ことを見つけた → 続きの印には出さない。同じ時間帯に別の実績があると列が約24pxになり文字が収まらないことは、仕様書の「表示の限界」に記録した
  - R3: 読み上げ名がボタン内の文字を置き換え、省略していることが伝わらず、本体と印が同じ名前になっていた → 省略の文言も名前に含める / R4: 再計測ボタンより文字が前面に出てボタンが隠れる → ボタンを `z-[2]` / R5: 斜線・3日以上の継続のテストを追加
  - 教訓: 表示の要件(「読める」)は、実際の寸法で目視しないと確かめられない。テストを先に書いても、期待値そのものが仕様と違えば誤りを固定してしまう
