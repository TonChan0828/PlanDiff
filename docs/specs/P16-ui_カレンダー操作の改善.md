# 仕様書: カレンダー操作の改善(P16-ui)

- ステータス: 承認済み(2026-09-30、調査で列挙した改善の実施指示)
- 関連: P2-4 / P2-5 / P6-3 / P8-1 / P11-1 / P12-1
- 指示資料: `docs/指示資料/` を確認。今回の追加資料なし

## 目的

モバイルの編集パネルが一覧に隠れる問題、削除確認時のフォーカス漏れ、日またぎ予定の編集導線の欠落、日付の参照更新による不要なレイアウト再計算を直す。

## 仕様

### 編集パネルと一覧

- コンテキスト一覧から予定・実績の編集を開始したら、モバイル用一覧シートを閉じて編集パネルを表示する。定期予定の編集対象選択も同様。
- デスクトップの常設一覧は引き続き表示する。
- 保存や削除の処理、エラー表示、遅延ロードは既存の挙動を維持する。

### フォーカス

- ダイアログ内で表示内容や無効状態が変わっても、現在操作できる要素の間で Tab / Shift+Tab を循環させる。
- 削除確認への切替でフォーカス要素が消えた場合は、ダイアログ内の先頭の操作可能要素へ移す。全要素が無効ならダイアログ本体で保持する。
- `tabindex=-1`、非表示、無効化された要素は循環対象にしない。
- Escape による閉じる操作と、閉じた後の元要素へのフォーカス復元は維持する。

### 日またぎの一覧

- 予定・確定済み実績の一覧は、タイムラインと共通の期間重なり判定で抽出する。開始日が前日でも表示日に重なれば一覧から編集できる。
- 当日0時に終了した項目や翌日0時に始まる項目は除外する。ゼロ長実績はタイムラインと同じ扱いを維持する。
- 日またぎ項目は開始・終了の両方に日付を併記する。同日内の時刻表示は変更しない。
- 編集時は切り詰めた表示区間ではなく、保存済みの元の開始・終了日時を渡す。

### 再計算

- 明示された表示日、今日の日付、週の日付配列を安定化し、一覧開閉などの操作だけでは予定・実績のレイアウトを再計算しない。
- 表示日、予定・実績データ、現在時刻に依存する実行中実績が変化した場合は必要な再計算を行う。日付またぎの自動更新は維持する。

## スコープ外

DB/APIの変更、予定・実績の配色やレーン配置変更、カレンダー全体の再設計、新規ライブラリ追加。

## テストシナリオ

- S1 [結合]: モバイル一覧から通常予定・定期予定・実績を編集すると、一覧シートが閉じて対応する編集ダイアログが表示される。
- S2 [結合]: デスクトップで編集しても常設一覧は残る。
- S3 [結合]: 予定・実績・定期予定の削除確認へ切り替えるとフォーカスがダイアログ内にあり、Tab / Shift+Tab が新しい操作要素間で循環する。
- S4 [単体]: 操作要素が全て無効になったダイアログでは Tab で外へ移動せず、失敗後に再有効化された要素へ操作を戻せる。
- S5 [単体]: Escape で閉じる処理を呼び、アンマウント時に元のボタンへフォーカスを復元する。
- S6 [単体]: 前日から続く予定・実績が選択日の一覧に表示され、日付を含む時刻が表示される。
- S7 [単体]: 当日0時に終了、翌日0時に開始した項目は一覧から除外し、当日0時のゼロ長実績は表示する。
- S8 [結合]: 前日開始の予定を翌日の一覧から編集すると、元の開始・終了日時が編集パネルに渡る。
- S9 [結合]: 明示日の日表示・週表示で一覧を開閉しても、予定・実績のレイアウト計算回数が増えない。
- S10 [結合]: 表示日や予定データが変化した場合はレイアウトが再計算され、内容も更新される。
- S11 [結合]: 今日表示で分が進んでも同日の予定レイアウトを再計算せず、翌日へ進むと表示とレイアウトが更新される。
- S12 [実ブラウザ]: 375×667で通常予定・定期予定・実績を一覧から編集し、フォームが隠れず入力・保存できる。削除確認のキーボード循環も確認する。統合時に担当者が実施する。

DBの仕様は変えないため、結合検証はコンポーネント間連携で行う。共通の全件検証・375px実ブラウザ検証・作業ログと計画書更新は統合担当が実施する。
