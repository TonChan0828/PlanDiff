## 目的

初回ロードの転送量と、操作時の再計算コストを減らす。
P6-1(サーバー往復)・P6-2(DBクエリ)でサーバー側は片付いたので、残るクライアント側に取りかかる。

**自前のアプリコードは小さい**(`/calendar` 専用チャンクは gz 14KB)。
重いのはライブラリの取り込み方と、メモ化がまったく無いことによる再計算である。

### 実際に使っている書式

`format()` の第2引数を全件洗い出した結果、**ロケール依存のトークンは `E`(曜日略称)だけ**だった。

| 書式 | 使用箇所 | ロケール依存 |
|---|---|---|
| `HH:mm` ×13 / `yyyy-MM-dd` ×3 / `d` ×2 | 各所 | なし(数値のみ) |
| `yyyy年M月d日` / `M月d日` / `yyyy年M月` | カレンダー・サマリー | なし(`年月日`は非ASCIIのため素通し) |
| `E` / `M/d(E)` / `M月d日(E)` / `yyyy年M月d日(E)` | カレンダー・計測・サマリー | **あり(`E`のみ)** |

`ja` locale から実際に使っているのは `localize.day(i, { width: "abbreviated" })`
= `日,月,火,水,木,金,土` の 7 語のみ。

## 仕様

### 3-A: `date-fns/locale` の `ja` を最小 locale に置換【効果最大】

`lib/ui/ja-locale.ts` を新設し、`localize.day` の abbreviated だけを実装した
最小 locale を定義する。`components/calendar-view.tsx` /
`components/track-view.tsx` / `components/calendar-context-panel.tsx` /
`lib/summary/format.ts` の 4 箇所の import を差し替える。

- **出力が現在の `ja` と1文字も変わらないことを、使用中の全書式について単体テストで固定する**
- `date-fns` の `Locale` 型を満たす必要があるため、`format()` が参照しうる
  `localize` の各関数と `formatLong` は用意する。ただし本アプリが使わない幅・トークンは
  実装せず、呼ばれたら例外を投げる(将来 `P` などを使い始めたときに気づけるようにする)
- `options.weekStartsOn` は既存コードが `startOfWeek(d, { weekStartsOn: 1 })` と
  明示指定しているため locale に依存しない。それでも `ja` と同じ値を持たせる

### 3-B: `next.config.ts` に `optimizePackageImports`

現在の `next.config.ts` は create-next-app のテンプレートのまま(実質空)。

```ts
experimental: { optimizePackageImports: ["date-fns", "lucide-react"] }
```

3-A と併せて barrel 由来の取り込みを潰す。
`@supabase/supabase-js` は対象外(tree-shaking しにくく、認証4ページのみで使われる)。

### 3-C: `rangeIsEmpty` の捨て計算を除去

`components/calendar-view.tsx:744`:

```ts
const rangeIsEmpty =
  days.length > 0 && days.every((day) => layoutDayEvents(events, day).length === 0);
```

「空メッセージを出すか」の判定**だけ**のために全日分のレイアウト計算をフル実行して結果を捨てている。
同じ `layoutDayEvents(events, day)` は直後に `DayColumn` 内でもう一度走るため、
週表示では **7日 × 2回 = 14回**の完全なレイアウトパスになる。
`lib/calendar/layout.ts` の中身は全イベントの `parseISO` × 2 → `differenceInMinutes` → sort → クラスタリング。

「その日と重なるイベントが1件でもあるか」の軽量判定に置き換える。
**判定結果は現在と完全に一致させる**(同じ日付集合・同じ重なり条件)。

### 3-D: `DayColumn` のメモ化

`DayColumn` は `useMemo` も `React.memo` もなく、`layoutDayEvents` × 2 と
`computeActualGaps` を毎レンダー再計算する。`CalendarView` の**任意の state 変更**
(パネル開閉、`contextTab` 切替、`timerPending`、`eventError` 設定…)で
週表示なら 7 列ぶんまるごと再計算される。

メモ化を阻んでいる不安定参照を先に潰す必要がある。順序は次のとおり。

1. `now`(毎レンダー `new Date()`)を安定化する
2. `actualInputs`(毎レンダー新規配列)を `useMemo` に
3. `onBlockTap` / `onEditActual` / `onRestartActual` を `useCallback` に
4. `DayColumn` 内の `blocks` / `actualBlocks` / `gaps` を `useMemo` に
5. 仕上げに `DayColumn` を `React.memo`

**`now` の扱いについて(重要)**: 現在の `now` は「`CalendarView` が再レンダーされたときにしか
更新されない」ため、現在時刻ラインと実行中ブロックの高さは既に自動追従していない(既存の挙動)。
**今回はこの挙動を変えない**。安定化するだけに留める。
追従させるなら分単位 tick の新設が必要で、それは別項目とする。

### 3-E: `CalendarContextPanel` の毎レンダー filter/sort

`components/calendar-context-panel.tsx` の `filter` + `parseISO` + `sort` を `useMemo` 化する。
デスクトップ(`lg:` 以上)では常時マウントされているため、親の全再レンダーで走っている。

併せて `getDesktopSnapshot` が呼ばれるたびに `window.matchMedia()` で
`MediaQueryList` を新規生成しているのをモジュールスコープのキャッシュに変える
(`useSyncExternalStore` の `getSnapshot` はレンダーごとに呼ばれる)。

### 3-F: 編集パネル群の遅延ロード

`AppEventPanel` / `EditEntryPanel` / `EditStartPanel` / `RecurringRulePanel` /
`RecurringEditChoicePanel` は「開いたときだけ」レンダーされるのに静的 import で初回ロードに含まれる。
これらが引きずる `DateTimeStepper`(343行)も同様。`next/dynamic` で遅延ロードする。
`track-view.tsx` の `AppEventPanel` / `EditStartPanel` も同じ。

**注意**: パネルはフォーカストラップ(`lib/ui/use-dialog-focus.ts`)を持つ。
遅延ロード後もフォーカス移動が壊れないことを確認する。
既存のパネル系コンポーネントテストが `next/dynamic` 経由で解決できるか(vitest 環境での挙動)を
**実装の最初に小さく確認する**。解決できない場合は 3-F を落とし、その旨をログに残す。

### 3-G: sticky バーの `backdrop-blur` 撤去

`components/running-timer-bar.tsx` / `components/free-timer-bar.tsx` が
スクロールコンテナ上の sticky 要素で `backdrop-filter` + `shadow-lg` を使っている。
モバイルのスクロールジャンクの典型的な原因。`bg-surface/95` があるため視覚的にはほぼ同等。

## スコープ外

- **認証4ページの supabase-js 248KB(gz 65KB)削減**。Server Action 化すれば
  `/login` の First Load を 789KB → 540KB 程度にできるが、認証フロー全体の書き換えになる
- **`components/calendar-view.tsx`(1472行)の分割**。保守性の課題であり、
  性能への寄与は 3-D / 3-F でほぼ取り切れる
- **`HourLines` の 168 div を CSS グラデーションに統合**。効果が小さく、
  オーバーレイの見た目(プロダクトの「顔」)に触るリスクに見合わない
- **現在時刻ラインの分単位追従**。既存挙動の変更にあたるため別項目
