- `next` / `eslint-config-next` のmajor downgradeは行わない。
- S-3の調査記録PRでは `package.json`、`package-lock.json`、workflow、アプリコードを変更しない。S-1の運用方針に従い、今回のCI失敗と依存修正を同じPRへ混在させない。

## スコープ

### 今回含むもの

- Advisory、CVE、CI失敗箇所、依存経路、上流issue、`npm audit fix --force` の不適切な提案を記録する。

## 再開条件と修正時の確認

以下のいずれかが起きたらS-3を再開し、別PRで依存更新を実施する。

1. Advisoryまたは上流issueに`braces`の修正版が公開され、依存チェーンに互換性を保った形で適用できる。
2. `micromatch`または上位パッケージが修正版を取り込み、監査対象経路を安全なバージョンへ解決できる。
3. Advisoryの影響範囲・修正情報が変更され、現行lockfileに対する評価をやり直す必要が生じる。

再開後は、修正版の互換性と解決経路を確認し、必要最小限の依存変更を行う。`npm ci`後に`npm audit --audit-level=high`を実行し、TypeScript、lint、テスト、本番build、CIを確認する。監査の失敗を閾値変更や例外化で解消してはならない。互換性のある修正がなお存在しない場合は、その根拠と再評価時点を更新して上流パッチ待ちを継続する。
