# 仕様書: G-104 長時間の実績が週表示のスケールを壊さないようにする

- ステータス: 承認済み(2026-11-27)
- 関連: GitHub Issue #104 / [P3-1](P3-1_オーバーレイ表示.md) / [G-91](G-91_タイマーの止め忘れ対策.md) / [G-99](G-99_細かい表示の改善.md)
- 指示資料: なし(2026-11-27 に確認。README のみ)

## 目的

止め忘れなどの長時間の実績があると、週表示がその1件の帯(超過の斜線ハッチ)に覆われ、他の予定・実績が読み取りにくい。

## 現況

- 実績ブロックの高さは実際の長さのまま。超過の斜線(`GapStripe`)は予定の終了から実績の終了まで伸びる
- 列の割り当て(`layoutDayEvents`)は長さで重なりを判定するため、長い実績は他の実績を細い列に押し込む

## 仕様

- **週表示だけ**で、長さが **8時間以上**の完了した実績を省略表示する(閾値は定数。承認時に8時間で確定)。日表示は実際の長さのまま(正確な時間を確かめる画面を残す)
- 省略表示は、**開始から2時間ぶんの高さ**にする
  - 下端を、切れ目と分かる形(ギザギザの境界)にし、ブロック内に「省略 12時間38分」と実際の長さを文字で出す
  - 超過の斜線も、省略したブロックの下端までにする
  - **列の割り当てより前に**縮める(表示だけを縮めると、他の実績が細い列に押し込まれたままになるため)
- 日をまたぐ省略対象は、開始日の列にだけ2時間ぶんを出す。続きの日の列には、最小の高さの印「前日から継続(省略)」を出し、タップで同じ編集パネルが開く
- **集計・ズレの数値・編集の対象は変えない**。`aria-label` と `title` は実際の開始・終了を示す。タップすると編集パネルが開き、実際の時刻を直せる
- 実行中のタイマーは省略しない(伸びていることが分かるようにする。警告は G-91)
- 省略の判定は純粋関数(`lib/calendar/long-entry.ts`)に置き、元の開始・終了は書き換えない。DB の変更はない

## スコープ外

- 時間軸に区切りを入れる方式(全列の座標が変わり、ほかの表示と整合させる範囲が大きいため)、日表示の省略、省略を切り替える設定

## テストシナリオ

日時はローカルTZで組み立てる(R-1)。

- J1 [単体・境界]: 7時間59分は省略しない、8時間ちょうどは省略し表示の終了が開始+2時間になる。元の時刻は変わらない。実行中は省略しない
- J2 [単体]: 日をまたぐ場合の、開始日と続きの日の表示範囲
- J3 [単体]: 省略後の範囲で列を割り当てると、省略対象の後半の時間帯の実績が全幅になる
- J4 [画面]: 週表示で「省略 12時間38分」が出て、超過の斜線が省略ブロックを超えない。日表示は従来どおり
- J5 [画面]: `aria-label`・`title` は実際の時刻。タップで開く編集パネルの時刻も実際の値
- J6 [画面]: 日をまたぐ実績の続きの日に印が出て、タップで編集パネルが開く
- J7 [UI]: 375px の週表示で省略ブロックの文字が読める(スクリーンショットで確認)
