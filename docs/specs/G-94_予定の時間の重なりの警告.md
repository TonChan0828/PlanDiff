# 仕様書: G-94 予定の時間が重なるときに警告する

- ステータス: 承認済み(2026-11-27)
- 関連: GitHub Issue #94 / [P2-5](P2-5_アプリ内予定とGoogle連携凍結.md) / [P5-1](P5-1_定期予定.md)
- 指示資料: なし(2026-11-27 に `docs/指示資料/` を確認。README のみ)

## 目的

予定どうしの時間が重なっていても気づけない。登録・編集の時点で重なりを知らせる。保存はできる。

## 現況

- 予定の保存経路は2つ: `AppEventPanel`(単発の作成・編集、定期予定の作成。カレンダーと計測画面で使用)と `RecurringRulePanel`(繰り返し全体の編集)
- どちらも重なりを確かめていない。週・日のグリッドは重なる予定を左右に並べるだけ

## 仕様

- 2つのパネルで、入力中の時間が既存の予定と重なる場合、保存ボタンの上に**入力に合わせて更新される警告**を出す。保存は止めない(確認ダイアログは足さない)
  - 文言: 「ほかの予定と時間が重なっています(保存はできます)」+ 重なる予定を最大3件(「11/22(日) 10:20〜10:50 副業」)。4件以上は「ほか N件」
  - `role="status"` にし、色だけに頼らず文言とアイコンで示す
- **重なりの定義**: 半開区間。`A.start < B.end かつ B.start < A.end`。終了と開始が同じ時刻(10:00 終了と 10:00 開始)は重ならない
- 編集中の予定そのものは対象外。繰り返し全体の編集では、同じルールの回(`rec:<ルールid>:`)を除く
- 繰り返し全体の編集では、**今日以降の日**だけを調べる(保存で作り直すのは今日以降の回のため。P5-1)(実装時に追記)
- **定期予定(作成・繰り返し全体の編集)**: 繰り返し条件の曜日に当たる日で、開始日〜終了日の範囲にある既存の予定と、時刻帯が重なるかを調べる
- **調べられる範囲**: 画面が読み込んでいる予定(表示週の前後1週間。計測画面も同様)だけ。範囲外の日の重なりは検出できない。入力の日が範囲外のときは何も出さない(「重なりなし」とは表示しない)
- 判定は純粋関数(`lib/calendar/overlap.ts`)に置く。DB・Server Action は変えない。文言は `lib/calendar/messages.ts` に集約する

## スコープ外

- 提案の「この週に追加」・「毎週にする」(ワンクリックの追加。同名の予定は既存の条件で除外される)
- Google 同期の予定の編集、保存済みの重なりをグリッド上で目立たせる表示、サーバー側の重複禁止

## テストシナリオ

日時はローカルTZで組み立てる(R-1)。

- H1 [単体]: 一部が重なる・包含する・同一時刻 → 重なり。隣接(終了=開始)・離れている → 重なりなし
- H2 [単体]: 編集中の予定の id は除く。日またぎの予定とも判定できる
- H3 [単体]: 定期条件(毎日・平日・毎週の複数曜日)で、条件に合う日の予定だけを返す。開始日より前・終了日より後の日は除く。同じルールの回は除く
- H4 [画面]: 重なる時間を入力すると警告と対象が出て、重ならない時間にすると消える。警告中でも保存できる
- H5 [画面・境界]: 4件以上重なる場合は3件と「ほか N件」。入力が未完成・終了が開始以前なら出さない
- H6 [画面]: 繰り返し全体の編集パネルでも警告が出る。自分の回では出ない
- H7 [画面]: カレンダーと計測画面の両方のパネルに予定が渡っている
- H8 [UI]: 375px で警告が崩れず、保存ボタンまで届く(横はみ出しは R-2 の共通関数)

R-1: 日時テストは `TZ=UTC` と `TZ=Pacific/Kiritimati` でも実行する。
