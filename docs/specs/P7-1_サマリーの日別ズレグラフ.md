- ステータス: 承認済み(2026-08-09)

  docs/specs/D-3_サマリーヒーローとLP.md / docs/specs/P5-9_サマリーの任意期間表示.md
- 指示資料: `docs/指示資料/` に本タスク関連の資料なし(README のみ。2026-08-09 確認)

## 目的

サマリーページ(`/summary`)に**期間内の日ごとのズレ**を発散棒グラフで表示し、
「いつズレたか」を一目で掴めるようにする。

現状のサマリーは P3-2 → D-3 → P5-3 → P5-8 → P5-9 → P6-0 と6段階で積み上がり、
数値表示としては完成しているが、**表示は最後まで数字とテキストだけ**でグラフが1つもない。
P5-9 で任意期間表示(今日/今週/今月/カスタム)まで実現したものの、
同仕様書の「スコープ外」筆頭に「期間ごとの推移グラフ・チャート表示」が先送りとして記録されている
(`docs/specs/P5-9_サマリーの任意期間表示.md:109`)。本タスクはその残りを埋める。

プロダクトの核心価値「見積もりが当たるようになる」は、1日単位のズレではなく
**期間をまたいだ傾向**が見えて初めて効く(P5-9 の目的欄)。
今週のズレ合計が `+0:55` であっても、それが「毎日+8分ずつ」なのか「水曜だけ+1時間」なのかで
打つ手はまったく違う。ヒーローの合計値だけではこれが区別できない。

### スコープ判断(ユーザー確認済み・2026-08-09)

要件定義書 §10 の料金表は「傾向分析」を Pro(構想)に、§4.2 は「v2の目玉」に分類している。
本タスクは **既存の集計結果(`computeGapSummary` と同一の集計規則)を図にするだけ**で、
新しい分析・見積もり係数の学習・サジェストは一切行わないため、
FR-07 の拡張として MVP に含める、とユーザーが判断した。

### ユーザーとの検討経緯(2026-08-09)

「サマリー画面でグラフィカルに情報を確認できる案を検討して」から発生。brainstorming で以下を確定:

- 見たいもの = 「いつズレたか(日別推移)」と「何に時間を使ったか(内訳)」の2軸
  → **本仕様書は前者のみ**を扱う。後者は P7-2 として分割(両者とも `lib/summary/chart.ts` と
    `page.tsx` を触るため並行できず、1本にまとめるとシナリオが50件超になるため)
- 推移の形 = 計画/実績の並べ棒でも重ね棒でもなく、**ズレだけの発散棒**
  (既存 diff ヒーローの `+0:55` 表記・柿/群青の色規約と思想が完全に一致するため)
- レイアウト = 既存リストは**一切変えず**、その上にグラフを差し込む
- 実装手段 = **チャートライブラリを導入しない**。手書き SVG + Tailwind
  (直前の P6-3 がバンドル削減のタスクであり、recharts 等は `"use client"` 必須で
   現状クライアントJSが実質ゼロのサマリー画面を一気に太らせるため)
- 操作性 = **完全に静的**。`"use client"` を追加せず、詳細は SVG `<title>` と `aria-label` で補う

## 仕様

### 表示イメージ

```
日別のズレ

 +2h ┤
      │       █
 +1h ┤ █     █       █
      │ █  █  █   █   █
   0 ┼─█──█──█───█───█────────
      │    █             █
 -1h ┤                   █
      8/3            8/6            8/9

 ↑ 超過   ↓ 不足
 最大超過 8/6 +1:20 ・ 最大不足 8/9 -2:10
```

- 期間の各日に1本ずつ棒を立てる。**0を基準に、超過(実績>計画)は上向き・不足は下向き**。
- 色は既存トークンに従う: 超過 = 柿 `--interrupt`(`fill-interrupt`)、不足 = 群青 `--brand`(`fill-brand`)。
  これは diff ヒーローの符号別の色分け(`page.tsx:261-265`)と同一の意味論。
- 見出しは既存セクションと同じ `text-ink-muted text-sm font-semibold`(`page.tsx:303`)。

### 表示条件

`resolved.dayCount >= 2` のときのみ描画する。

- `range=today` は常に1日なので描かない。
- **単日のカスタム期間(`from === to`)も描かない**。棒1本になり diff ヒーローと同じ数字の
  重複表示にしかならないため(`formatRangeLabel` が `dayCount === 1` を today と同じ扱いに
  している既存判断(`format.ts:91`)と揃える)。
- `resolved.error === "too-long"`(367日以上)のときは既存の early return(`page.tsx:204`)で
  グラフを含むページ本体に到達しないため、追加の分岐は不要。

### データ(集計)— 新規 `lib/summary/chart.ts`

```ts
export interface DailyGapPoint {
  /** その日のローカル0時 */
  date: Date;
  planMinutes: number;
  actualMinutes: number;
  /** actualMinutes - planMinutes。正=超過・負=不足 */
  gapMinutes: number;
  /** 予定も実績も0件の日。「ズレがちょうど0の日」と区別する */
  isEmpty: boolean;
}

export function computeDailyGapSeries(
  planEvents: SummaryPlanEvent[],
  actualEntries: SummaryActualEntry[],
  range: SummaryRange,
): DailyGapPoint[];
```

- `GapSummary` には日付情報がない(`GapSummaryItem` は分数のみ)ため、
  **生の `planEvents` / `actualEntries` を入力に取る**。`page.tsx` が `computeGapSummary` に
  渡しているのと同じ2値をそのまま渡す。
- **集計規則は `computeGapSummary` と完全に一致させる**(P3-2 から不変):
  「**開始時刻が期間内**」のものだけを対象とし、その**開始日に全量を計上**する。
  日をまたぐ実績(23:00〜01:00)は開始日に120分まるごと乗る。
- 実績は予定への紐づきの有無(`googleEventId`)を問わず、すべて `actualMinutes` に加算する
  (割り込み・フリー作業も「その日に使った時間」なのでズレに寄与する。
   これは `computeGapSummary` の `actualTotalMinutes`(`aggregate.ts:171-173`)と同じ扱い)。
- 戻り値は必ず `dayCount` 個の要素を、期間の初日から昇順で返す(データのない日も `isEmpty: true` で埋める)。

**この規則により次の不変条件が成立し、ヒーローの数値とグラフが絶対に食い違わない。
これをテストで固定する(S10。本仕様書で最も重要な保証)**:

```
Σ points[i].planMinutes   === computeGapSummary(...).planTotalMinutes
Σ points[i].actualMinutes === computeGapSummary(...).actualTotalMinutes
Σ points[i].gapMinutes    === computeGapSummary(...).gapMinutes
```

日バケットの決定は `differenceInCalendarDays(parseISO(startAt), range.start)`。
`range.start` / `range.end` は `startOfDay` / `startOfWeek` / `startOfMonth` 由来のローカル0時
(`range.ts:74-82`)なのでそのまま使える。
`lib/summary/range.ts` は import しない(`aggregate.ts ← range.ts` の依存方向を崩さないため)。

### `lib/summary/aggregate.ts` の変更(挙動不変)

private な2関数を export するだけ。集計ロジックの重複実装を避けるのが目的。

| 現在 | 変更後 |
|---|---|
| `function durationMinutes(...)`(`aggregate.ts:88`) | `export function durationMinutes(...)` |
| `function inRange(...)`(`aggregate.ts:92`) | `export function isStartInRange(...)` にリネーム(内部呼び出し2箇所を差し替え) |

挙動は一切変えない。既存の `tests/lib/summary/` 9本が無改修で通ることで回帰を保証する。

### 表示(フォーマット)— `lib/summary/format.ts` に追加

グラフコンポーネントに文言を持たせず、すべて純関数に切り出してテスト可能にする
(既存の `formatRangeLabel` / `formatSummaryCounts` と同じ流儀)。

| 関数 | 出力例 |
|---|---|
| `formatChartDayLabel(date)` | `"8/3"` |
| `formatDailyGapPointTitle(point)` | `"8月3日 +1時間20分(計画 2時間 / 実績 3時間20分)"`。ズレ0の日は `"±0分"` |
| `formatDailyGapChartLabel(points, rangeLabel)` | `"日別のズレ(2026年8月3日〜8月9日)。最大超過 8月6日 +1時間20分、最大不足 8月9日 -2時間10分"`。ズレのある日が0本なら末尾を `"ズレのある日はありません"` にする |
| `formatDailyGapExtremes(points)` | 極値行 `"最大超過 8/6 +1:20・最大不足 8/9 -2:10"`。超過のみ/不足のみなら該当分だけ。ズレ0なら `null`(行を描かない) |

- 日付整形は `date-fns` の `format(date, "M/d")` / `"M月d日"` を使う。
  **曜日トークン(`E`)を含まないためロケール引数は不要**(P6-3 で最小化した `jaMinimal` に依存しない)。
- 分数の整形は既存の `formatSignedDurationMinutes` / `formatSignedClockMinutes` /
  `formatDurationMinutes` を再利用する。
- 文言は `lib/summary/messages.ts` の `SUMMARY_MESSAGES` に追加する(ハードコード禁止):
  `dailyChartHeading: "日別のズレ"` / `dailyChartOver: "超過"` / `dailyChartUnder: "不足"` /
  `dailyChartMaxOver: "最大超過"` / `dailyChartMaxUnder: "最大不足"` / `dailyChartNoGap: "ズレのある日はありません"`。

### 描画 — 新規 `components/summary-daily-gap-chart.tsx`

**Server Component(`"use client"` を付けない)。**

```tsx
export function SummaryDailyGapChart({ points, rangeLabel }: {
  points: DailyGapPoint[];
  rangeLabel: string;
}): React.JSX.Element
```

props は計算済みの値のみ。Supabase クライアントも `SummaryRange` も渡さないため、
コンポーネントテストがモックなしで書ける(既存 `page.test.tsx` の `vi.mock` 4連発が不要)。

**描画方針: SVG 内にテキストを一切置かない。**
`preserveAspectRatio="none"` で横方向に自由伸縮させ、日数2〜366のどれでもコンテナ幅に
ぴたりと収める。軸ラベルは SVG の外に HTML で置く(文字が潰れない / `truncate` が効く / 将来のi18n可)。

```
CHART_H = 100   // viewBox の高さ(単位)
ZERO_Y  = 50    // 0軸
HALF    = 44    // 上下それぞれの最大バー高(上下6ずつ余白)
SLOT    = 10    // 1日あたりの横幅
MIN_BAR = 1.2   // 0でないズレが消えないための最小高
GAPLESS_MIN_DAYS = 63   // これ以上の日数では棒間の隙間をなくす
DENSE_MAX_DAYS   = 7    // これ以下なら全日ラベル、超えたら3個に間引く

viewBox = `0 0 ${dayCount * SLOT} ${CHART_H}`
maxAbs  = Math.max(1, ...points.map(p => Math.abs(p.gapMinutes)))
barH    = |gap| === 0 ? 0 : Math.max(MIN_BAR, (|gap| / maxAbs) * HALF)
barW    = dayCount >= GAPLESS_MIN_DAYS ? SLOT : SLOT * 0.68
```

- **上下で同じ `maxAbs` を使う**。+60分 と -30分 が高さ 44 と 22 になり、上下の比較が成立する。
- 0軸線は `vectorEffect="non-scaling-stroke"` を**必ず付ける**。
  `preserveAspectRatio="none"` 下では stroke が横方向に潰れ、線が消える/不均一に太る。
- 各棒には `data-sign` と `data-date`(`yyyy-MM-dd`)を付け、テストが浮動小数の `y`/`height` に
  依存せず符号を検証できるようにする。

| 状態 | 描画 | `data-sign` |
|---|---|---|
| `gapMinutes > 0` | `y = ZERO_Y - barH`、`fill-interrupt` | `over` |
| `gapMinutes < 0` | `y = ZERO_Y`、`fill-brand` | `under` |
| `gapMinutes === 0` かつ `!isEmpty` | 0軸上に高さ `MIN_BAR` の中立スタブ(`fill-ink-muted opacity-40`) | `zero` |
| `isEmpty` | 棒を描かない(0軸のみ) | `empty` |

- 各棒は `<g><title>{formatDailyGapPointTitle(p)}</title><rect .../></g>` で包む。
  マウスホバーでネイティブのツールチップが出る(クライアントJSなし)。
- **X軸ラベル(HTML、SVG の下)**:
  - `dayCount <= DENSE_MAX_DAYS`: `grid` を `dayCount` 列に切って全日 `8/3` 表記(`text-[10px]`)
  - それ以上: **初日 / 中間日 / 最終日の3個のみ**を `flex justify-between` で(366日でも3ノード)
- **凡例**: `↑ 超過` / `↓ 不足` を色チップ付きで1行。
  **上下の向き自体が色以外の手がかり**になるため、ここでハッチ(斜線)は使わない
  (`preserveAspectRatio="none"` でパターンが歪み、日数が多いとストライプが潰れて逆効果になる)。
- **極値行**: SVG 直下に `formatDailyGapExtremes(points)` の結果を `font-mono tabular-nums` で1行。
  これが「値を直接読める」手段になる(密な期間では全日にラベルを振れないため)。

**375px での成立根拠**(実測値): コンテンツ幅 = 375 − `px-4`×2 = **343px**。
棒幅は 7日 → 33px / 31日 → 7.5px / 366日 → 0.94px。366日でも隙間をなくすことで
密度のシルエット(スパークライン相当)として読める。
**日数が増えても DOM は rect 1つ/日で済み、テキストノードは増えない**のがこの設計の要点。
高さは `h-32`(128px)/ `sm:h-40`。

### アクセシビリティ

- セクションは `<section aria-labelledby="daily-gap-chart-heading">` + `<h2 id="...">`。
- SVG に `role="img"` と `aria-label={formatDailyGapChartLabel(points, rangeLabel)}` を付ける。
  スクリーンリーダーには「日別のズレ(2026年8月3日〜8月9日)。最大超過 8月6日 +1時間20分、
  最大不足 8月9日 -2時間10分」という要約が届く。
- 個別の棒の `<title>` は `role="img"` の親の下にあるため二重読み上げにならない。
- **色以外の手がかり**(ui-quality スキルの規約): ①棒の**向き**(上=超過 / 下=不足)という形、
  ②凡例のテキスト、③極値行の数値。この3つで色を使わずに意味が通る。
- 366日ぶんの `sr-only` テーブルは**作らない**。DOM が数千ノード膨らみ、
  スクリーンリーダーでの読み上げもかえって不可能になるため、要約 aria-label + 可視の極値行で代替する。

### `app/(app)/summary/page.tsx` の変更

`page.tsx:301` の右カラム `<div className="flex min-w-0 flex-col gap-8">` の**先頭**に挿入する。

```tsx
const showDailyChart = resolved.dayCount >= 2;
const dailyPoints = showDailyChart
  ? computeDailyGapSeries(planEvents, actualInputs, resolved.range)
  : [];
```

モバイル(375px)では `lg:grid-cols-*` が効かず1カラムに落ちるため、DOM 順のまま
[期間タブ][diffヒーロー][日別のズレ][予定ごとの内訳][割り込み・フリー作業] と縦に並ぶ。
デスクトップでは左カラム(sticky のタブ+ヒーロー)の右に [日別のズレ][既存リスト2つ] が入る。

**既存の「予定ごとの内訳」「割り込み・フリー作業」のマークアップは1行も変更しない。**

- DBスキーマ変更なし。マイグレーションなし。

### 結合テストを追加しない理由(承認が必要な判断)

本タスクは **DBスキーマ変更なし・新規のデータ取得なし**で、`page.tsx` が既に取得済みの
`planEvents` / `actualInputs` を使い回すだけである。Route Handler / Server Action / RLS を
跨ぐ経路は一切増えないため、`tests/integration/` への新規追加は行わない。

代わりに、
1. S10 の**不変条件テスト**が `computeGapSummary`(結合テスト `tests/integration/summary.test.ts` で
   実DBを通して検証済み)との一貫性を保証し、
2. S32〜S36 の画面統合テストがページ全体のレンダリング経路を通す

ことで網羅する。既存の結合テスト124件が無改修で通ることを完了条件に含める。

**この判断はユーザー承認済み(2026-08-09)。** P5-3 / P5-8 は表示追加のみながら結合を1件ずつ
足しているが、両タスクは `computeGapSummary` の**出力フィールドを増やした**のに対し、
本タスクは集計関数を一切変更せず既存の入力から別ビューを導出するだけであるため、
実DBを通す新規経路がない。
