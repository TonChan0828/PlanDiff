## 目的

サマリーページ(`/summary`)に**実績時間の作業タイトル別の内訳**を横棒グラフで表示し、
「何に時間を使ったか」を一目で掴めるようにする。

P7-1 で「**いつ**ズレたか」(日別のズレ)は見えるようになったが、「**何に**時間が消えたか」はまだ
数値リストを上から読まないとわからない。既存の「予定ごとの内訳」は**ズレの大きい順**に並んでおり、
「時間を多く使った順」ではない。さらに割り込み・フリー作業は別セクションに分かれているため、
**1日/1週間の時間の使い道を1つの図で俯瞰する手段が存在しない**。

2026-08-09 の brainstorming でユーザーが選んだ2軸のうち後半にあたる
(前半の「いつズレたか」は P7-1 で実装済み)。

### スコープ判断(P7-1 と同じ。ユーザー承認済み・2026-08-09)

要件定義書 §10 は「傾向分析」を Pro/v2 に分類しているが、本タスクは
**既存の集計結果(`GapSummary`)を図にするだけ**で、新しい分析・見積もり係数の学習・
サジェストは一切行わない。よって FR-07 の拡張として MVP に含める。
要件定義書は v0.7 の FR-07「グラフ可視化」節に記載済み。

## 仕様

### 表示イメージ

```
時間の内訳

■ 予定に紐づく実績   ■ 割り込み・フリー

設計レビュー                      4時間50分
████████████████████████
予定 4時間50分

実装                                  50分
████
予定 50分

問い合わせ対応                        45分
███▓
予定 15分・割り込み 30分

その他(4件)                           40分
███
予定 25分・割り込み 15分
```

- 実績のある作業を**タイトルで集約**し、**実績時間の多い順**に横棒で並べる。
- 棒は `予定に紐づく実績`(群青 `--brand`)→ `割り込み・フリー`(柿 `--interrupt`)の**積み上げ**。
- 見出しは既存セクションと同じ `text-ink-muted text-sm font-semibold`(`page.tsx:303`)。
- P7-1 の日別ズレグラフの**直後**、既存の「予定ごとの内訳」の**前**に置く。

### 表示条件

**期間の長さによらず常に表示する**(P7-1 と異なり、単日でも「今日の時間の使い道」として意味を持つため)。

- `range=today` でも表示する。
- 実績が1件もない期間は、グラフを描かず空メッセージ(`breakdownEmpty`)を出す。
- `resolved.error === "too-long"`(367日以上)は既存の early return(`page.tsx:204`)で
  ページ本体に到達しないため、追加の分岐は不要。

### データ(集計)— `lib/summary/chart.ts` に追加

```ts
export interface ActualBreakdownRow {
  /** isOther のときは空文字。表示文言は format 側で組み立てる */
  title: string;
  /** plannedMinutes + unplannedMinutes */
  actualMinutes: number;
  /** 予定に紐づく実績(群青) */
  plannedMinutes: number;
  /** 割り込み・フリー作業(柿) */
  unplannedMinutes: number;
  /** 通常行は畳んだ予定+割り込みの件数、isOther 行は畳んだタイトル数 */
  count: number;
  isOther: boolean;
}

export interface ActualBreakdown {
  rows: ActualBreakdownRow[];
  /** 全行の合計。丸め込みの前後で不変 */
  totalMinutes: number;
  /** 棒の正規化に使う。rows の最大値(「その他」行を含めた後の最大) */
  maxMinutes: number;
  /** 畳まれたタイトル数。0 なら丸めなし */
  otherCount: number;
}

/** 「その他」に畳むまでに表示する行数の上限 */
export const BREAKDOWN_TOP_N = 8;

export function computeActualBreakdown(
  items: GapSummaryItem[],
  interruptions: InterruptionItem[],
  options?: { limit?: number },
): ActualBreakdown;
```

**生データは不要**。`computeGapSummary` の出力(`summary.items` と `summary.interruptions`)から
完全に導出できる。P7-1 の `computeDailyGapSeries` が生の `planEvents`/`actualEntries` を要したのは
日付情報が `GapSummary` に無かったためで、こちらはタイトルと分数だけで足りる。

集計規則:

1. `items` のうち **`actualMinutes > 0`** のものを、`title` をキーに `plannedMinutes` へ合算する。
   未着手(`actualMinutes === 0`)の予定は**行に含めない**(「時間の内訳」なので0分の行は意味がない)。
2. `interruptions` を `title` をキーに `unplannedMinutes` へ合算する。
3. **1と2で同じタイトルが現れたら1行に統合する**(例: 予定「レビュー」の実績60分 +
   フリー計測「レビュー」30分 → 1行で `plannedMinutes: 60` / `unplannedMinutes: 30` /
   `actualMinutes: 90`)。「何に時間を使ったか」が目的なので、同じ作業名を2行に割ると目的に反する。
   どちらか一色に丸めると値が嘘になるため、行内で内訳を保持する。
4. 並び順は **`actualMinutes` 降順 → `title.localeCompare` 昇順**
   (既存 `groupInterruptionsByTitle`(`aggregate.ts:276-279`)と同じ規約)。
5. **丸め込み**: 行数が `limit`(既定 `BREAKDOWN_TOP_N = 8`)を超える場合、
   上位 `limit` 件を残し、残りを「その他」1行に畳む。
   ただし**畳む対象が1件しかないときは丸めない**(「その他(1件)」は情報の劣化でしかないため、
   `limit + 1` 件ちょうどのときは全件表示する)。
   「その他」行は `isOther: true`、`count` = 畳んだタイトル数、`title` は空文字。
6. **「その他」行は大きさに関係なく常に配列の末尾**に置く。
7. `totalMinutes` は全行の `actualMinutes` の合計。**丸め込みの前後で変わらない**(総和保存)。
8. `maxMinutes` は**丸め込み後**の `rows` の `actualMinutes` の最大値。
   小さい行が多数畳まれて「その他」が最大になるケースがあり、丸め込み前の値を使うと
   棒の幅が100%を超える。空なら `0`。

### 表示(フォーマット)— `lib/summary/format.ts` に追加

| 関数 | 出力例 |
|---|---|
| `formatBreakdownKinds(row)` | 予定のみ: `"予定 4時間50分"` / 割り込みのみ: `"割り込み 45分"` / 混在: `"予定 15分・割り込み 30分"` |
| `formatBreakdownOtherTitle(count)` | `"その他(4件)"` |

- 分数の整形は既存の `formatDurationMinutes` を再利用する。
- 区切りは既存の `SUMMARY_MESSAGES.countsSeparator`(`"・"`)を再利用する。
- 文言は `SUMMARY_MESSAGES` に追加する(ハードコード禁止):
  `breakdownHeading: "時間の内訳"` / `breakdownEmpty: "この期間の実績はありません"` /
  `breakdownPlanned: "予定"` / `breakdownUnplanned: "割り込み"` /
  `breakdownLegendPlanned: "予定に紐づく実績"` / `breakdownLegendUnplanned: "割り込み・フリー"` /
  `breakdownOther: "その他"`。

### 描画 — 新規 `components/summary-actual-breakdown.tsx`

**Server Component(`"use client"` を付けない)。**

```tsx
export function SummaryActualBreakdown({ breakdown }: {
  breakdown: ActualBreakdown;
}): React.JSX.Element
```

**行のレイアウトとテキストは HTML、棒だけ inline SVG。**
タイトルは可変長で `truncate` が要り、値は右揃えのテキストで出す必要がある。
テキストを SVG に入れると 375px で確実に破綻する
(P7-1 が「SVG内にテキストを置かない」方針を取ったのと同じ理由)。
「チャートライブラリを入れず手書き SVG + Tailwind で描く」という決定は満たしている。

各行の構造(3段):

```tsx
<li data-testid="breakdown-row" className="flex flex-col gap-1">
  {/* 1段目: タイトル(truncate)と合計時間(右揃え・等幅) */}
  {/* 2段目: 棒 */}
  <svg viewBox="0 0 100 6" preserveAspectRatio="none" aria-hidden="true" className="h-2 w-full">
    <rect x={0} y={0} width={plannedPercent} height={6} className="fill-brand" />
    <rect x={plannedPercent} y={0} width={unplannedPercent} height={6} className="fill-interrupt" />
  </svg>
  {/* 3段目: 内訳文言(formatBreakdownKinds) */}
</li>
```

- 正規化は **`maxMinutes` 基準**(最上位行が常に全幅)。
  合計基準にすると上位行が細くなり、行同士の比較がしづらくなる。
  `plannedPercent + unplannedPercent <= 100` は `maxMinutes` の定義から保証される。
- `maxMinutes === 0` のときは0除算しない(そもそも `rows` が空なので描画に到達しない)。
- **幅0の `rect` は描かない**(単色の行に空要素を出さない)。
- `isOther` 行のタイトルは `formatBreakdownOtherTitle(count)`。
- 行は `<ul>` / `<li>` で構成し、既存リスト(`page.tsx:309`)と同じ `flex flex-col gap-2` に揃える。

### アクセシビリティ

- セクションは `<section aria-labelledby="actual-breakdown-heading">` + `<h2 id="...">`。
- **棒の SVG は `aria-hidden="true"`**。値は隣接するテキスト(合計時間と内訳文言)が読み上げるため、
  棒にも `aria-label` を付けると二重読み上げになる。
- **色以外の手がかり**(ui-quality スキルの規約): `formatBreakdownKinds` が
  常に `予定 15分・割り込み 30分` のように**テキストで内訳を出す**。
  加えてセクション先頭に凡例1行(色チップ + `予定に紐づく実績` / `割り込み・フリー`)を置く。
  色が見えなくても行の意味が完全に伝わる。
- 構造は `<ul>`/`<li>` なのでスクリーンリーダーに件数と項目がそのまま通る。
  P7-1 のような要約 `aria-label` は不要(行数が最大9行に丸められており、読み上げが実用的なため)。

## スコープ外

- 「その他」行の展開・折りたたみ(`"use client"` の追加を伴う)
- ホバー/タップのツールチップ、行のクリックによるドリルダウン
- ドーナツ/円グラフ形式(タイトル数が可変で凡例が破綻しやすく、長さの比較も横棒に劣る)
- 計画時間の内訳(本タスクは**実績**の使い道のみを扱う。計画との対比は既存のヒーローと
  「予定ごとの内訳」の担当)
- 未着手の予定を0分の行として出すこと(「時間の内訳」の趣旨に合わない。
  未着手の情報は既存の件数ステータス行と「予定ごとの内訳」の未着手バッジが担う)
- タイトルが空文字の実績への表示上の手当て(`CALENDAR_MESSAGES.untitled` への差し替え等)。
  既存の「予定ごとの内訳」「割り込み・フリー作業」も同様に素通ししており、
  本タスクだけ挙動を変えると不整合になる。直すなら別タスクで全箇所まとめて行う
- タイトルの表記ゆれの吸収(大文字小文字・全角半角・前後の空白)。完全一致で集約する
- 上位N件のユーザー設定
- 移動平均・傾向分析・見積もり係数の学習(要件定義書 §4.2 の v2 スコープ)

### 結合テストを追加しない理由(承認が必要な判断)

P7-1 と同じ理由。本タスクは **DBスキーマ変更なし・新規のデータ取得なし**で、
`computeGapSummary` の出力を再集計して描画するだけである。
Route Handler / Server Action / RLS を跨ぐ経路は一切増えない。

`computeGapSummary` 自体は既存の結合テスト(`tests/integration/summary.test.ts`)で
実DBを通して検証済みであり、その出力を入力とする本タスクの純関数は単体テストで十分に閉じる。
S30〜S34 の画面統合テストがページ全体のレンダリング経路を通す。

既存の結合テスト124件が無改修で通ることを完了条件に含める。

**この判断はユーザー承認済み(2026-08-10)。** 併せて次の個別判断も承認済み:
同名の予定+割り込みは1行に統合 / 上位8件+「その他」/ 畳む対象が1件なら丸めない /
`range=today` でも表示 / 未着手は行に含めない。
