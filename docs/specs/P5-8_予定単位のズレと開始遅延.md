# 仕様書: P5-8 予定単位の「ズレ%・開始遅延」可視化

- ステータス: 承認済み(2026-07-25)
- 関連: docs/要件定義書.md の FR-07(ギャップサマリー)/ docs/specs/P3-2_ギャップサマリー.md / docs/specs/P5-3_サマリー件数ステータス行.md
- 指示資料: `docs/指示資料/` に本タスク関連の資料なし(README のみ。2026-07-25 確認)

## 目的

サマリーページ(`/summary`)の「予定ごとの内訳」で、予定単位の**振り返りの解像度**を上げる。
現状は各予定に「計画◯分 / 実績◯分」と「ズレ(符号付き分)」しか出ておらず、
「予定に対して何割ズレたか」「予定より何分遅れて着手したか」がわからない。

本タスクは、P5-3(サマリー件数ステータス行)で**明示的に「将来検討」として見送った2項目**
(`docs/specs/P5-3_サマリー件数ステータス行.md:66-67`)を実装する:

1. **予定単位のズレ%** … その予定の見積もりを何%外したか(例: `+37%`)
2. **開始遅延** … 予定の開始時刻に対し、実際に着手したのが何分早い/遅いか(例: `+14分遅れ`)

これにより、プロダクトの核心価値「見積もりが当たるようになる」を予定ごとの粒度まで下ろす。

ユーザーとの検討経緯(2026-07-25):
- 方向性 = 提案①「ズレ%・開始遅延の可視化」を選択(v2の係数学習・サジェスト、期間拡張はやらない)
- DB変更なし・既存 `computeGapSummary` の入力は不変で、算出フィールドの追加と表示のみ

## 仕様

### 表示イメージ(予定ごとの内訳の各行)

```
設計タスク                          +22分 (+37%)
計画 1時間 / 実績 1時間22分
着手 予定より +14分遅れ

朝会                                 -5分 (-17%)
計画 30分 / 実績 25分
着手 予定より +2分遅れ

ドキュメント作成                         未着手
計画 45分 / 実績 0分
（開始遅延は表示しない）
```

- ズレ%は既存のズレ(符号付き分)の直後に併記する(例: `+22分 (+37%)`)。
- 開始遅延はタイトル下のメタ行(計画/実績)の下に、着手済みの予定にのみ1行で表示する。
- 未着手(`notStarted`)の予定は従来どおり「未着手」バッジのみで、ズレ%・開始遅延は表示しない。

### データ(集計)

`lib/summary/aggregate.ts` の `GapSummaryItem` に以下2フィールドを追加する
(集計対象・範囲判定は P3-2 から変更しない。予定・実績とも「開始時刻が範囲内」のものが対象):

| フィールド | 定義 |
|---|---|
| `gapPercent` | `planMinutes === 0` のとき `null`、それ以外は `Math.round((gapMinutes / planMinutes) * 100)`。ヒーロー全体の `gapPercent`(既存、`aggregate.ts:126-129`)と同じ丸め規約に揃える |
| `startDelayMinutes` | 未着手(`actualMinutes === 0`)のとき `null`。着手済みなら「その予定に紐づく実績のうち**最早の開始時刻** − 予定開始時刻」を分で返す(`differenceInMinutes(最早実績開始, 予定開始)`)。**正 = 遅れ、負 = 早着手** |

- 最早の実績開始時刻は、`computeGapSummary` の実績ループ(`aggregate.ts:86-103`)で
  eventId ごとに `Map<string, string>`(ISO文字列)へ集約する。同一予定に複数実績が
  紐づく場合は最も早い開始を採用する。
- `startDelayMinutes` の算出には予定開始時刻 `event.startAt` を用いる(`items` 生成時、`aggregate.ts:105-116`)。

### 表示(フォーマット)

- **ズレ%**: 既存 `formatSignedPercent`(`format.ts:38-42`)を再利用(例: `+37%` / `-17%` / `0%`)。
- **開始遅延の分**: 既存 `formatSignedDurationMinutes`(`format.ts:19-22`)を再利用(例: `+14分` / `-3分` / `0分`)。
- 開始遅延の**行全体の文言**は `lib/summary/messages.ts` の `SUMMARY_MESSAGES` に追加する
  (例: `startDelayLabel: "着手 予定より"`、`startDelaySuffix: "遅れ"`)。ハードコードしない。
  - `startDelayMinutes > 0`(遅れ): `着手 予定より +14分遅れ`
  - `startDelayMinutes < 0`(早着手): `着手 予定より 3分早い`(符号なしの絶対値+「早い」)
  - `startDelayMinutes === 0`(定刻): `着手 予定どおり`
- `app/(app)/summary/page.tsx` の内訳 `<li>`(`157-181行`)を改修:
  - ズレ%は既存のズレ表示(`data-testid` を新設: `gap-item-gap`)に併記。`gapPercent === null` のときは%を出さない。
  - 開始遅延はメタ行の下に `data-testid="gap-item-start-delay"` の1行として描画。`startDelayMinutes === null`(未着手)のときは要素自体を出さない。
  - スタイルは既存メタ行に準拠(`text-ink-muted` の小さめテキスト、数字は `tabular-nums`)。375px 幅で横スクロールを発生させない(自然に折り返す)。

### データ変更・エラー時の挙動

- DBスキーマ変更なし。新規データ取得なし(`computeGapSummary` の入力・呼び出し箇所は不変)。
- エラーハンドリングの追加なし(既存のページのエラー挙動を変えない)。

## スコープ外

- 見積もり係数の学習・計画時サジェスト(v2の目玉)
- 期間の月次拡張、按分、ソート・フィルタ(P3-2/P5-3 のスコープ外事項を維持)
- 割り込み・フリー作業(`interruptions`)側への%・遅延表示(紐づく予定がなく定義できない)
- 予定単位のズレ%・開始遅延をヒーローや件数ステータス行へ集計表示すること(内訳の各行のみ)
- 実行中タイマー(未確定実績)を開始遅延の算出対象に含めるかの特別扱い
  (`actualBlockInputs` が返す確定・実行中の別なく、範囲内の最早開始を採用する既存挙動に従う)

## テストシナリオ

対応テストファイル: `tests/lib/summary/aggregate.test.ts` / `tests/lib/summary/format.test.ts` /
`tests/app/(app)/summary/page.test.tsx` / `tests/integration/summary.test.ts`(既存構造にならう)。
各テスト名にシナリオID(S1等)を含める。

### 正常系

- S1 [単体]: Given 計画60分・実績82分の予定1件(実績開始が予定開始の14分後) When `computeGapSummary` Then その item の `gapPercent === 37`・`startDelayMinutes === 14` を返す
- S2 [単体]: Given 計画30分・実績25分の予定(実績開始が予定開始の2分後) When `computeGapSummary` Then `gapPercent === -17`(-16.67の四捨五入)・`startDelayMinutes === 2`
- S3 [単体]: Given ある予定に実績が2件紐づき、開始が 10:20 と 10:05(予定開始10:00) When `computeGapSummary` Then `startDelayMinutes === 5`(最早の10:05を採用)
- S4 [コンポーネント]: Given 着手済みの予定1件(gapPercent・startDelayMinutes あり) When サマリーページ描画 Then `gap-item-gap` にズレ%が併記され、`gap-item-start-delay` に開始遅延の文言が表示される

### 異常系 / エッジ

- S5 [単体]: Given `planMinutes === 0` の予定(0分予定に実績あり) When `computeGapSummary` Then `gapPercent === null`
- S6 [単体]: Given 未着手の予定(実績0分) When `computeGapSummary` Then `startDelayMinutes === null`・`gapPercent`(=`Math.round((-planMinutes/planMinutes)*100)` = -100)を返す
- S7 [コンポーネント]: Given 未着手の予定 When サマリーページ描画 Then `gap-item-start-delay` 要素が存在せず、%も表示されない(従来どおり「未着手」バッジのみ)

### 境界値

- S8 [単体]: Given 実績開始が予定開始より前(早着手。予定10:00・実績09:52開始) When `computeGapSummary` Then `startDelayMinutes === -8`
- S9 [単体]: Given 実績開始が予定開始と同時刻 When `computeGapSummary` Then `startDelayMinutes === 0`
- S10 [単体]: Given `startDelayMinutes` が正/負/0 When `formatSummaryStartDelay`(または page 側の文言組み立て)Then それぞれ `+N分遅れ` / `N分早い` / `予定どおり` の文言になる
- S11 [結合]: Given 予定と実績を投入した既存の結合フロー(`tests/integration/summary.test.ts`)When `computeGapSummary` まで通す Then 追加フィールド `gapPercent`・`startDelayMinutes` が期待値で算出される(既存シナリオを壊さない)
