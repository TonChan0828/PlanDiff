# P10-3: 学習補正の対象拡大と再計測の集約

- ステータス: 承認済み(2026-11-20)
- 関連: [P10-1](P10-1_提案経由予定の学習補正.md) / [P10-2](P10-2_予定調整と休止提案.md) / docs/要件定義書.md FR-13
- 指示資料: なし(2026-11-20 に `docs/指示資料/` を確認。README のみ)
- 経緯: 2026-11-20 ユーザー報告「短くはなるが、時間が拡張される方には全然機能していない」。
  例として 19:30 開始の定期予定が、過去1か月は 18:00〜18:30 開始が大半なのに早まらない

## 目的

定期予定の自動調整が、短くする方向だけでなく、早める・延ばす方向にも実績どおり動くようにする。

## 本番調査(2026-11-20、読み取り専用クエリ)

計算(中央値→5分丸め→項目ごとに5分以上の差で採用)は向きによらず対称です。原因は次の2点でした。

1. **学習対象外のルール**: 例の 19:30〜22:15 の予定は `origin='manual'`、`last_learned_at` が null で、
   一度も判定されていない。42日間の28回すべてが予定に紐づき、最初の開始の中央値は 18:50、
   1回あたり合計所要の中央値は約228分(予定は165分)。`origin='manual'` の5件はすべて 2026-08-09 作成で、
   P10-1 の導入(2026-08-13)より前のため、提案経由かどうかを記録できなかった
2. **再計測の断片**: 中断→再計測(P5-4)で1回の予定に複数の実績が付く。断片を1件ずつ中央値に入れるため、
   所要は短く、開始は遅く寄る

| ルール | 予定所要 | 現行(実績1件ずつ) | 1回ごとに合計 |
|---|---|---|---|
| 8dc8d3c5 | 30分 | 29.7分 | 83分 |
| cf7674d4 | 35分 | 32.8分(短縮方向) | 42.8分 |
| 2aa22d65 | 25分 | 29.5分 | 43.5分 |

未紐づけの同名実績・日またぎ・休止中による除外は該当しなかった。

## 仕様

### 学習対象

- 作成経路(`origin`)に関係なく、すべての定期予定を学習の対象にする
- `recurring_rules.auto_adjust_enabled`(既定 `true`)が `false` のルールだけを除外する
- 「自動調整を止める」は `auto_adjust_enabled` を `false` にする。`origin` は作成経路の記録として変えない
- 「自動調整を止める」は、学習が有効なすべての定期予定の編集パネルに表示する
- 既存行はすべて `true` にする。本番で「自動調整を止める」を使った行はない
  (`origin='manual'` の5件はトグルがなかった時期の作成)
- 休止提案(P10-2)の対象は今回変えず、`origin='suggestion'` のままにする

### 1回分の実績の集約

- 同じ `google_event_id`(`rec:<ruleId>:<日付>`)の完了実績を1回分としてまとめる
- 開始時刻は、その回で最も早い実績の開始とする。所要時間は各実績の所要の合計とする
- 42日の範囲は、その回の最初の開始で判定する
- 最低3件の条件と、通知に表示する件数は「回数」で数える
- 中央値・5分丸め・項目ごとの5分閾値・24:00超の除外・7日の再学習間隔は変えない

### データ変更

`supabase/migrations/<timestamp>_recurring_rule_auto_adjust.sql`

- `recurring_rules` に `auto_adjust_enabled boolean not null default true` を追加する
- `apply_recurring_rule_learning` の対象判定を `r.origin <> 'suggestion'` から `not r.auto_adjust_enabled` に変える。
  引数・戻り値・権限は変えない
- 既存テーブルへの列追加のため、RLS ポリシーと GRANT は変わらない

### エラー時の挙動

P10-1/P10-2 と同じ。学習の保存に失敗したルールは調整を飛ばし、カレンダーの表示は止めない。
停止操作の失敗はパネル内にエラーを表示し、トグルを残す。

### 導入順序

1. マイグレーションを本番へ適用する
2. アプリを公開する(新アプリは `auto_adjust_enabled` を読むため、P17-2 のゲートに従い SQL を先に適用する)

## スコープ外

- 停止した自動調整を再開する導線
- 休止提案の対象を手動作成の予定へ広げること
- 同じタイトルの未紐づけ実績を学習に含めること(P10-2 の方針どおり紐づけはIDだけで行う)
- 調整履歴の永続化・一覧・取り消し
