# 仕様書: G-98 実績の編集フォームに予定とのズレを表示する

- ステータス: 承認済み(2026-11-26)
- 関連: GitHub Issue #98 / [P2-4](P2-4_実績の手動編集.md) / [P3-1](P3-1_オーバーレイ表示.md) / [P5-8](P5-8_予定単位のズレと開始遅延.md)
- 指示資料: なし(2026-11-26 に確認。README のみ)

## 目的

実績の編集フォームでは、予定とのズレをその場で確認できない。時刻を直しながらズレの変化が分かれば、止め忘れの修正などがしやすくなる。

## 現況

- `components/edit-entry-panel.tsx` は、タイトル・開始・終了だけを持つ。呼び出し元は `calendar-view.tsx` の1箇所
- 週表示の差分ラベル(`computeActualGaps`)は、分割された実績では「最初の断片の開始遅延」と「最後の断片の超過」を出し、早着手・不足は出さない
- サマリー(P5-8)は、予定ごとに紐づく実績を合計し、「所要の差 = 実績合計 − 予定」「開始の差 = 最も早い実績の開始 − 予定の開始」(早い場合は負)を出す

## 仕様

- 編集中の実績が予定に紐づき(`googleEventId` があり)、その予定が画面のデータにある場合、開始・終了の入力の下に「予定とのズレ」欄を表示する
  - 予定の時刻: 「予定 09:00〜10:00(1時間)」
  - 開始の差: 「開始 +8分 遅れ」「開始 5分 早い」「開始 予定どおり」
  - 所要の差: 「所要 +6分 超過」「所要 12分 不足」「所要 予定どおり」
- **計算はサマリー(P5-8)と同じ定義にする**: 同じ予定に紐づく実績(編集中の実績は入力中の値に置き換える)を合計し、開始の差は最も早い開始で出す。
  分割した実績の1つを開いたときに、断片だけの不足を大きく出さないため。2件以上の合計なら「同じ予定の実績 N件の合計」と添える
- 入力を変えると、差分がその場で更新される
- 入力が未完成、または終了が開始より前のときは、差の行を出さない(既存の入力エラーは保存時に出る)
- 紐づかない実績(フリー・割り込み)や、予定が画面のデータにない場合は、欄を出さない
- 色だけに頼らず、「遅れ・早い・超過・不足」の文言で区別する。文言は `lib/timer/messages.ts` に集約する
- 差分の計算は純粋関数(`lib/timer/gap.ts`)に置く。週表示の差分ラベルの仕様は変えない
- DB の変更はない

## スコープ外

- 週表示の差分ラベルの変更、予定側からの差分表示、実行中タイマーの編集

## テストシナリオ

日時はローカルTZで組み立てる(R-1)。

- E1 [単体]: 9:08〜10:14、予定 9:00〜10:00 → 開始 +8分、所要 +6分
- E2 [単体]: 早い開始・短い実績 → 開始・所要の差が負になる。ぴったり → どちらも0
- E3 [単体]: 同じ予定に2件の実績 → 所要は合計、開始は最も早いもの、件数は2
- E4 [単体・境界]: 別の予定の実績は合計に入らない。紐づきがない・予定がない → 差分なし(null)
- E5 [単体・異常系]: 終了が開始より前・不正な日時 → null
- E6 [画面]: 紐づく実績の編集で、予定の時刻と開始・所要の差が出る
- E7 [画面]: 終了時刻を変えると、所要の差がその場で更新される
- E8 [画面]: フリー実績の編集では欄が出ない。分割された実績では「N件の合計」が出る
- E9 [UI]: 375px の編集パネルで崩れがなく、保存ボタンまでスクロールで届く

R-1: 追加した日時テストは `TZ=UTC` と `TZ=Pacific/Kiritimati` でも実行する。
