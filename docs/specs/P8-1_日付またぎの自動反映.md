# 仕様書: P8-1 日付またぎの自動反映(カレンダー)

- ステータス: 承認済み(2026-08-11)
- 関連: docs/要件定義書.md の FR-03(カレンダービュー)/ docs/specs/P2-1_カレンダービュー.md
- 指示資料: なし(`docs/指示資料/` に本件に関する資料なし。2026-08-11 確認)
- 発生元: ユーザー報告(2026-08-11)「日にちをまたぐと自動で次の日の表示にしたい」

## 目的

`/calendar` を開いたまま深夜0時を過ぎても表示が翌日に切り替わらない不具合を解消する。
あわせて、同じ原因で止まっている現在時刻ラインなど「時刻」の表示も追従させる。

### 原因(調査結果)

1. **時刻の再レンダートリガーが存在しない**
   `components/calendar-view.tsx:198-204` は「今日」も「現在時刻」もレンダー中に素の `new Date()` を
   評価しているだけで、state にも外部ストアにも載っていない。
   アプリ内で `setInterval` を持つのは `lib/timer/use-now-seconds.ts` の1箇所のみで、これは
   `RunningTimerBar` / `RunningTimerHero` の内部で購読されているため親の `CalendarView` は再レンダーされない。
   `visibilitychange` / `focus` / `pageshow` のリスナは全画面でゼロ件(PWA復帰でも再描画されない)。

2. **URL が日付を固定してしまう**
   `buildCalendarPath`(`lib/calendar/view-date.ts:69`)は常に `?view=day&date=YYYY-MM-DD` を生成する。
   「今日」ボタン(`calendar-view.tsx:292`)や週ストリップのタップでもこの形式が push されるため、
   一度でも日移動すると「今日を見ているつもり」でも URL 上は特定日に固定される。
   `selectedDate` は `parseDateParam(dateParam) ?? 今日` の順で解決されるので、(1) を直すだけでは
   切り替わらない。

`app/(app)/layout.tsx:12` は `force-dynamic` なのでサーバー側キャッシュは原因ではない。
リクエストさえ飛べば常に最新日付でレンダーされる。純粋にクライアントが再描画しないことが問題。

## 仕様

### 1. 分単位の現在時刻を配信する共有ストア(新規 `lib/time/use-now-minute.ts`)

```ts
export function useNowMinuteMs(): number | null;
```

- `useSyncExternalStore` で購読する(`lib/timer/use-now-seconds.ts` と同じパターン)
- スナップショットは**分に丸めた epoch ms(number)**。`Date` を返すと毎回参照が変わり
  `useSyncExternalStore` が無限ループになるため必ずプリミティブにする
- サーバースナップショットは `null`。SSR(サーバーTZ)とクライアントTZの不一致を避けるため、
  「今日」「現在時刻」に依存する描画はハイドレーション完了後に行う(既存 `useHydrated` と同じ方針)
- **ストアはモジュールスコープに1つ**。購読コンポーネントごとにタイマーを張らない
- **分境界にアラインした `setTimeout` 連鎖**で駆動する。次回発火までの待ち時間は
  `MINUTE_MS - (Date.now() % MINUTE_MS)`。固定間隔の `setInterval` だと 00:00 の検知が
  最大60秒遅れるため、境界に合わせることで日付切り替わりを秒単位の遅れで拾う
- **`visibilitychange` / `focus` / `pageshow` でも即時に再計算**する。
  バックグラウンドタブのタイマースロットリングと、iOS PWA のプロセスサスペンドからの復帰に対応する
- 値が前回と同じ場合は購読者に通知しない(不要な再レンダーを起こさない)
- 購読者が0になったら `clearTimeout` とイベントリスナの解除を行う

`useNowSeconds` は秒精度が必要な実行中タイマー用なので統合せずそのまま残す。

### 2. 「URL の `date` は今日以外を見ているときだけ持つ」不変条件

`lib/calendar/view-date.ts` の `buildCalendarPath` に `today` 引数を追加し、
表示日が今日と同じ暦日なら `date` を付けない。

```ts
export function buildCalendarPath(
  view: CalendarViewMode,
  date: Date,
  today: Date | null,
): string
```

| `date` と `today` | 生成されるURL |
|---|---|
| 同じ暦日 | `/calendar?view=day` |
| 別の暦日 | `/calendar?view=day&date=2026-08-09` |
| `today` が `null`(ハイドレーション前) | `/calendar?view=day&date=2026-08-09`(常に付ける) |

サーバー側 `app/(app)/calendar/page.tsx:53` の `parseDateParam(dateParam) ?? new Date()` は変更しない。
これはデータ取得範囲(表示週±1週間)の算出専用で、TZ差・日跨ぎはバッファが吸収する。

### 3. 追従の条件

| 状態 | 0時通過後の挙動 |
|---|---|
| 今日を表示中(URL に `date` なし) | 新しい今日へ自動で切り替わる |
| 過去日/未来日を表示中(URL に `date` あり) | 表示日は変わらない |

(2) の不変条件により「今日を見ている」= `date` パラメータなし、と表現できるため、
前回の「今日」を保持して比較する必要はない。

### 4. `CalendarView` の変更(`components/calendar-view.tsx`)

- ローカル定義の `useHydrated` と `emptySubscribe`(156-163行)を削除する。
  `useNowMinuteMs() !== null` がハイドレーション完了と同値で役割が重複するため
- 198-204行を差し替える

```ts
const nowMinuteMs = useNowMinuteMs();
const now = useMemo(
  () => (nowMinuteMs === null ? null : new Date(nowMinuteMs)),
  [nowMinuteMs],
);
const today = useMemo(() => (now ? startOfDay(now) : null), [now]);
const selectedDate = parseDateParam(dateParam) ?? today;
```

- 744-754行で `now` から再計算していた `nowMinuteMs` はフックの戻り値をそのまま使う。
  `DayColumn` のメモ化粒度(分)は変わらない
- `buildCalendarPath` の呼び出し4箇所(288 / 293 / 297 / 882行)に `today` を渡す
- **日付が変わったらサーバーデータを取り直す**
  表示日が翌日に動いても props の `events` / `timeEntries` は前日基準の取得結果のまま。
  同週内の日跨ぎでは既存の同期 effect(`weekKey` 依存)が走らないため追従しない。
  `today` の日付キー(`yyyy-MM-dd`)が変化したときだけ `router.refresh()` を1回呼ぶ。
  初回の `null → 値`(ハイドレーション)では呼ばない。1日1回なのでコストは無視できる
- 初期スクロール effect(275-283行)の依存は `[view]` のまま変更しない。
  0時通過でスクロール位置が飛ぶのは操作の妨げになるため

### 影響を受ける既存の表示(いずれも `now` 経由で自動的に追従する)

- 現在時刻ライン(位置・`HH:mm` ラベル。1256-1268行)
- 週ストリップ / 週ビューヘッダの当日ハイライト(`aria-current="date"`)
- 実行中ブロックの高さ(`nowMinuteMs` 経由)

### 既存テストへの影響(仕様変更に伴う更新であり、無効化ではない)

- `tests/components/calendar-view.test.tsx` S8「ビュー切替」: 今日を表示中の遷移先が
  `?view=week&date=...` → `?view=week` になる
- 同 S9「今日ボタン」: 遷移先が `?view=day&date=...` → `?view=day` になる
- `tests/lib/calendar/view-date.test.ts` S5: `buildCalendarPath` の引数追加

## スコープ外

- `/track`: `lib/track/entry-groups.ts` の「今日」判定が固定され、0時通過後に当日の実績が
  未来日扱いで除外されうる(`components/track-view.tsx:70`)。同種の問題だが別項目とする
- `/summary`: `app/(app)/summary/page.tsx:90` の `new Date()` が**サーバーTZ**評価で、
  カレンダー/計測のクライアントTZ判定と非対称。`range=today` の追従はTZ是正とセットで扱うべき
- Service Worker の導入によるバックグラウンド更新(P3-3 の範囲外。MVPでは不要)
- ユーザー単位のタイムゾーン設定(現状どおり実行環境のTZに従う)

### タイムゾーン(CLAUDE.md R-1 の遵守)

- テストの日時は `new Date(2026, 7, 11, 23, 59)` のようにローカルTZで構築する。
  ISO文字列(`"2026-08-11T23:59:00Z"` 等)やオフセット付き文字列で固定しない
- 「今日」に依存するテストは `vi.useFakeTimers()` + `vi.setSystemTime()` で基準時刻を固定する
- コミット前に `TZ=UTC` と `TZ=Pacific/Kiritimati`(UTC+14)で対象テストを実行する

## 検証(手動)

- `/calendar` を開く → URL に `date` が付かない。「今日」ボタンを押しても付かない
- 前日へ移動 → `?view=day&date=...` が付く。「今日」で消える
- OSのシステム時刻を 23:59 にして `/calendar` を開き放置 → 00:00 で表示日が翌日に変わる
- 同じ操作を過去日(`?date=` 付き)で行い、**変わらない**ことを確認する
- 別タブに切り替えて数分後に戻る → 現在時刻ラインが即座に正しい位置へ来る
- 375px 幅(ライト/ダーク)で週ストリップ・現在時刻ラインの表示崩れがないこと
