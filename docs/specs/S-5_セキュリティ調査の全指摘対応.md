# S-5: セキュリティ調査の全指摘対応

- ステータス: 承認済み（2026-10-25、会話中の計画と「Implement the plan.」による承認）
- 関連: docs/security/2026-10-25.md。指示資料には追加資料なし。

## 目的

既知の依存脆弱性、削除例外の所有者確認、計測APIの乱用、画面保護と入力検証の不足を修正する。本番への変更は差分と検証結果を揃えてから提示する。

## 仕様

- Next.js/eslint-config-nextを16.4.3へ更新し、開発依存も修正版へ更新する。監査の除外・閾値緩和は禁止。
- recurring_exceptionsは参照先も本人所有であることをRLSと複合外部キーで保証する。既存の不一致行はprivateスキーマへ隔離する。重複エラー時も本人の例外の存在を確認する。
- 計測APIはJSONのみ、本文1024バイトまで、event一項目のみを受け付ける。設定済みの公開元に一致しないOriginは403、形式違反は415、本文超過は413、不正JSON/値は400。
- 正常時204。送信元ごと20件/分、全体600件/分をDB時刻の固定時間枠で制限する。判定・更新・保存は単一トランザクション。超過429とRetry-After。DB障害・設定不足は503。一般利用者は専用RPCを実行できない。
- IPはVercelの上書きするヘッダーのみ信頼し、秘密鍵と分単位の時間枠を用いたHMAC-SHA256で変換する。生IPや識別値をログ・イベントに保存しない。ローカルのテストだけ固定ループバックを許可する。
- カウンターは2分経過後に毎分清掃する。最長10分を超える滞留・ジョブ失敗を検査可能にする。DB障害・バックアップ等での物理消去保証と混同しない。プライバシー説明を更新する。
- CSPは全画面にリクエストごとのnonceを適用する。HTMLは動的生成・共有キャッシュ禁止。script-srcに本番unsafe-inline/unsafe-evalを含めない。既存の配置用style属性は許可。埋め込み禁止、object-src none、base-uri/form-action self、通信先は同一サイトと設定されたSupabaseのみ。開発時だけデバッグ用eval/ローカルWebSocketを許可する。
- ProxyはCSPと認証更新を分離し、マーケティング・ステートレス計測でAuthへ不要な通信をしない。nonce/CSPのリクエストヘッダーは必ずサーバーで上書きする。
- 更新処理は外部入力の型、タイトル200文字、識別子2048文字、実在日付・時刻・曜日・タイムゾーンを検証する。既存の長いタイトルの無変更更新と、本人の保存済み予定に一致するタイトルのコピーを許可し、勝手に切り詰めない。DB直接操作も同じ制限を受ける。
- ローカルAuthの最小パスワード長を8にする。本番の認証設定・適用履歴・配信ヘッダーは公開前チェックとして残す。

## テストシナリオ

- S1 [単体]: 設定済み送信元・正常JSONは保存へ進む。不正Origin/形式/値/余分な項目/サイズ超過を拒否する。
- S2 [単体]: ストリーム本文の1024バイト境界、Content-Lengthなし、壊れたUTF-8を検証する。
- S3 [単体]: HMACは同一時間枠・IPで安定、別時間枠/IPでは異なる。秘密鍵・IP不足は保存しない。
- S4 [結合]: 並行リクエストでも送信元20件、全体600件を超えない。時間枠を跨ぐと再開する。制限時はイベントを増やさない。
- S5 [結合]: 清掃で期限切れ識別値が消える。一般利用者はカウンター・専用関数・隔離データにアクセスできない。清掃異常を検知する。
- S6 [結合]: 他人の予定に対する削除例外の挿入/更新を拒否する。本人の削除例外は正常。削除した予定が再生成されない。
- S7 [単体]: 削除時の重複エラーでは本人の例外の存在を確認し、確認できなければ失敗する。
- S8 [単体]: CSPの許可先、開発/本番差分、nonceの上書き、マーケティングでのAuth省略を確認する。
- S9 [ブラウザー]: 全画面でnonce付きHTMLとヘッダーが一致し、リクエスト間で異なる。許可印なしのスクリプトとiframe埋め込みを拒否する。
- S10 [ブラウザー]: 375pxでログイン・テーマ・予定・タイマー・サマリー・通知・料金計測が動く。
- S11 [単体]: null/配列/型違い/長いタイトル/不正識別子/実在しない日時を保存前に拒否する。正常・境界値は通る。
- S12 [結合]: DB直接の新規/変更タイトルを制限し、既存値の無変更更新と保存済み予定タイトルのコピーを維持する。
- S13 [検査]: npm audit（全依存/本番依存）から今回の告知が消える。整形・型・lint・単体・結合・ブラウザー・本番ビルドを確認する。

- 清掃の監視は認証付き `GET /api/cron/security-health` で行う。最終清掃成功が3分以内・ジョブ有効・10分超の識別値なしで200、それ以外は503。レスポンスとログに識別値を含めない。本番の監視登録は反映時に実施する。

- 追加のDB検査で判明した `btree_gist` のpublic配置をextensionsスキーマへ移す。既存インデックスの参照先は保持する。

## 導入

DBマイグレーション、PRO_INTEREST_HMAC_SECRET、APP_ORIGINの設定を先行する。計測用機能の準備不足では503とし、回数制限を迂回しない。Preview検証後に公開する。本番設定未確認・未適用のまま全件完了としない。
