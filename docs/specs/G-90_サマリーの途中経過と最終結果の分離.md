## 目的

期間の途中(今日の10時、今週の水曜など)に見るサマリーは、まだ始まっていない予定の計画時間を分母に含めるため、
実態より大きくマイナスに見える(例: 10:20時点で今日のズレ -4:59 / -85%。夜の4:40の予定が含まれている)。
さらに途中経過の数字が最終結果と同じ見た目で出る。「ここまでの正しいズレ」を出し、途中経過だと分かるようにする。

## 現況

- `lib/summary/aggregate.ts` の `computeGapSummary` は「開始時刻が期間内の予定」を全件計画に入れる(未来の予定も含む)
- `lib/summary/chart.ts` の `computeDailyGapSeries`(日別グラフ・「最大不足」)も同じ規則。系列の総和がヒーローと一致する不変条件(P7-1 S10)がある
- `app/(app)/summary/page.tsx` が `now` を持っている(実行中タイマーの扱いに使用)

## 仕様

### 「経過した予定」の定義

- 基準時刻 `asOf`(= 画面表示時の現在時刻)に対して、**開始時刻 ≤ `asOf` の予定、または紐づく実績が1件でもある予定(前倒しで着手済み)**を
  「経過した予定」とする(実行中の予定も含む)。前倒し着手を含めるのは、含めないと、その実績が「割り込み」に化けて予定との紐づきが消えるため
- それ以外(開始時刻 > `asOf` かつ未着手)の予定は「これから」とし、ズレの計算(計画・実績・ズレ・ズレ%・件数・予定ごとの内訳・日別グラフ)から除く
- 実績は従来どおり全件を数える(実績は過去にしか存在しない)。割り込み実績も同じ
- 実行中の予定は全計画時間をそのまま分母に入れる(例: 9:00〜10:00の予定を9:30に見ると、実績30分に対し計画60分で -30分)。
  経過分だけに按分する案は取らない(予定単位のズレ・開始遅延(P5-8)の定義と食い違うため)。**要確認**(下の「確認事項」)

### 途中経過の判定

- 途中経過 = `期間.start ≤ asOf < 期間.end`(期間が進行中)。過去の期間(`asOf ≥ end`)・未来の期間(`asOf < start`)は途中経過でない
- 過去の期間は従来の集計と完全に同じ結果にする(`asOf ≥ end` なら全予定が「経過した予定」になるため、自然に一致する)
- 未来の期間は現状の表示のまま変えない(経過した予定が0件で意味のある差分がないため。スコープ外)

### 集計関数

- `computeGapSummary(planEvents, actualEntries, range, asOf?)` と `computeDailyGapSeries(planEvents, actualEntries, range, asOf?)` に、省略可能な第4引数 `asOf: Date` を追加する
  - 省略時は現状と同じ動作(全予定を数える)。既存テスト・呼び出しは変えずに通る
  - 指定時は開始時刻 > `asOf` の予定を、計画・内訳・件数・日別グラフのいずれからも除く
- 「経過した予定」の判定は共通関数 `selectElapsedPlans(plansInRange, actualsInRange, asOf)` にまとめ、ヒーロー集計と日別グラフで共用する
  (規則のズレを防ぐ。`isStartInRange` を共用する P7-1 と同じ方針)
- 「これから」の件数・計画分数は、`asOf` なしの集計(期間全体)と `asOf` ありの集計(ここまで)の差から求める。専用関数は設けない
- 不変条件 S10(日別系列の総和 = ヒーロー集計値)は `asOf` を揃えて渡した場合も保つ

### 表示(`app/(app)/summary/page.tsx` とヒーローのコンポーネント)

途中経過のときだけ次を足す(最終結果の表示は現状のまま):

- ヒーローの見出しラベルに「途中経過」バッジを付け、ズレの数字を最終値と区別する(補助文言「現時点まで」)
  - 色だけに頼らず文言とバッジで区別する(アクセシビリティ)。ヒーローのハッチ下線・色分けの規則は変えない
- 進み具合の行: 「経過した予定 N件 / 全 M件」(M は期間内の全予定件数)
- 「これから」の行: 「このあと 予定 K件(計画 H:MM)」。K が0なら出さない
- 文言は定数オブジェクト(既存の `S`)に1箇所で追加する(日本語・ハードコード集約の規約)
- 日別グラフ・「最大不足」は `asOf` 指定の系列を使い、未来の日・未来の予定による不足を含めない
- 時間の内訳(P7-2)は実績のみから作るため変更しない

### 実行時刻の扱い

- `asOf` は Server Component の `new Date()`(既存の `now`)を渡す。クライアントでの自動更新は行わない(リロードで更新。既存の挙動と同じ)

## エラー時の挙動

- 新しい失敗経路はない。期間・日付の不正入力時の既存フォールバックは変更しない

## スコープ外

- 未来の期間の表示変更
- 実行中の予定の按分計算
- 過去の確定済みデータの扱いの変更・DB変更(DBスキーマ変更なし)
- 途中経過の自動更新(ポーリング)

## 確認事項(承認時に判断してください)

1. 実行中の予定は「全計画時間」を分母に入れる(本仕様)でよいか。経過分按分にすると、予定単位のズレ(P5-8)と数字が食い違う
2. #103 の「グレーアウト」は採用せず、バッジ+文言+進み具合の行で区別する(色だけに頼らないため)でよいか

## テストシナリオ

時刻は `vi.useFakeTimers` + `setSystemTime` で固定し、日時は `new Date(2026, 10, 21, 10, 20)` のようにローカルTZで組み立てる(R-1)。

- A1 [単体]: Given 朝・昼・夜の3予定、`asOf` 10:20 When `computeGapSummary` Then 夜の予定は計画・件数・内訳から除かれ、
  ズレは「朝・昼」だけで計算される(Issueの実例: 計画 5:50→1:10 相当に減る)
- A2 [単体・境界]: Given 開始 = `asOf` ちょうど When 集計 Then 含まれる(≤)。開始 = `asOf` + 1分 Then 除かれる
- A3 [単体]: Given 実行中の予定(開始 < `asOf` < 終了) When 集計 Then 計画は全時間で数える
- A4 [単体]: Given 過去の期間(`asOf` ≥ 期間終了) When `asOf` 付きで集計 Then 省略時と完全に同じ結果
- A5 [単体]: Given 未来の期間(`asOf` < 期間開始) When 集計 Then 判定は途中経過でない(表示は現状のまま)
- A6 [単体]: `asOf` 省略時は全予定を数える(既存テストの回帰)
- A7 [単体・境界]: Given 経過した予定が0件(早朝に見る) When 集計 Then 計画0・ズレ0・ズレ%は null(0除算なし)
- A8 [単体]: Given 割り込み実績 When `asOf` 付き Then 実績として従来どおり数える
- A9 [単体]: Given 未来の予定の実績を前倒しで記録済み When `asOf` 付きで集計 Then その予定は「経過した予定」として計画・実績とも数え、割り込みにならない
  (日別系列も同じ判定で、S10 の総和一致を保つ)
- A10 [単体]: Given `asOf` 付きの日別系列 When 未来の日 Then 計画0のため「最大不足」に現れない。
  系列の総和がヒーロー集計値と一致する(S10 の `asOf` 版)
- A11 [コンポーネント]: Given 途中経過 When ヒーローを描画 Then 「途中経過」バッジ・「経過した予定 N件 / 全 M件」・「このあと」行が出る
- A12 [コンポーネント]: Given 過去の期間 / 「これから」が0件 When 描画 Then バッジと「このあと」行は出ない
- A13 [結合]: Given DBに今日の朝・夜の予定と朝の実績 When サマリーのデータ取得〜集計 Then Issueの実例どおり夜の予定がズレに入らない
  (`summary.test.ts` の方式。RLS越しの取得を通す)
- A14 [UI/手動]: 375px幅で今日・今週の途中経過がバッジ付きで崩れない(ライト/ダーク。Playwright)

R-1: 追加・変更した日時テストは `TZ=UTC` と `TZ=Pacific/Kiritimati` でも実行する。
