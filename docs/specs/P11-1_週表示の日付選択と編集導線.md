## 目的

週表示(`/calendar?view=week`)で、今日以外の曜日にある予定・実績を編集できるようにする。

### 原因

予定・実績の編集は `CalendarContextPanel`(画面右/下部のパネル)の鉛筆ボタン経由でのみ可能で、
予定ブロック自体のタップはタイマー開始/停止に固定されている(`handleBlockTap`。これは日付に
関わらず正しく動作する仕様どおりの挙動であり、本対応の変更対象ではない)。

`CalendarContextPanel` は `selectedDate`(1日分)の予定・実績のみを表示する設計
(`components/calendar-context-panel.tsx:52-65`)。この `selectedDate` を変更する手段は、
日表示にある `WeekStrip`(曜日タップで日付を切り替えるUI、`components/calendar-view.tsx:1132-1170`)
のみで、**週表示には同等のUIが存在しない**。週表示の日ヘッダー行
(`components/calendar-view.tsx:923-944`)は非対話的な `<div>` のままで、`onClick`を持たない。

この経緯は、元々(P2-5仕様)予定ブロックそのものに編集ボタン(✎)が付いており曜日に関係なく
編集できていたものが、「UIをレスポンシブに再設計」コミット(`c113d9c`)で `CalendarContextPanel`
方式に置き換えられた際、週表示側で日付を選び直す手段の実装が漏れたことによる
(対応する仕様書更新もされていない、未文書化のリグレッション)。

## 仕様

### 方針(plan modeでユーザー承認済み)

週表示の日ヘッダーセル(月〜日の7列)をタップ可能な `<button>` にし、日表示の `WeekStrip` と
同じ考え方で `selectedDate` を切り替えられるようにする。切り替え後は既存の
`CalendarContextPanel` がその日の予定・実績を表示し、鉛筆ボタンから編集できる
(`CalendarContextPanel` 自体の変更は不要)。

### 変更内容: `components/calendar-view.tsx`

現状の週表示ヘッダー(923〜944行目)の `<div key={toDateParam(day)} data-week-day-header ...>` を
`<button>` に置き換える。

- `type="button"`
- `onClick={() => router.push(buildCalendarPath("week", day, today))}`
  - `view` は `"week"` 固定(`WeekStrip.onSelect` は `"day"` 固定だが、こちらは週表示内の
    日付選択なので週表示のまま遷移する)
  - `buildCalendarPath` が「今日を指すときは `date` パラメータを付けない」不変条件(P8-1)を
    自動的に守るため、呼び出し側で分岐は不要
  - `disabled`は付けない。週表示ヘッダー自体が `{view === "week" && selectedDate ? ... : null}`
    という条件で、`selectedDate`(≒`today`がまだ確定していない、かつURLにも`date`が
    無いハイドレーション前)が無いときはそもそも描画されないため。`today`が`null`のまま
    クリックされるケース(URLに`date`が明示されておりハイドレーション未完了)でも、
    `buildCalendarPath`は`today`が`null`なら`date`を省略しない(安全側に倒れる)ため
    追加のガードは不要と判断した
- 状態表示は `WeekStrip`(1154〜1160行目)と同じ3パターンをそのまま踏襲する
  - `isSelected = isSameDay(day, selectedDate)`
  - `isToday = now && isSameDay(day, now)`
  - 選択中: `border-brand bg-brand text-brand-ink font-semibold`
  - 今日(未選択): `border-brand/50 font-semibold`
  - どちらでもない: `text-ink-muted`
  - 現状の今日判定の背景色 (`bg-brand text-brand-ink font-semibold`) は「選択中」と
    見た目上同じ表現になるため、今日かつ未選択の状態を区別できるよう `WeekStrip` の
    3状態スタイルにあわせる(現状コードの2状態から3状態に拡張)
- `aria-pressed={isSelected}` / `aria-current={isToday ? "date" : undefined}` を付与する
- `aria-label={format(day, "M月d日(E)", { locale: ja })}`(`WeekStrip`と同じ形式)を付与する
- グリッドレイアウト(`grid-cols-[2.5rem_repeat(7,minmax(0,1fr))]`)を保つため、ボタンは
  セル幅いっぱいに広げる(`w-full`)。既存の `className`(`flex flex-col items-center
  rounded-md py-1 text-xs`)をベースに、ボタン要素として不要なデフォルトスタイルの
  リセットが必要なら追加する
- `data-week-day-header` 属性は維持する(既存テスト・スタイルフックとの互換のため)

### 影響を受けないコード

- `components/calendar-context-panel.tsx` — 既に `selectedDate` に反応する設計のため無改修
- `handleOpenEditEvent` / `handleEditTimeEntry` / `AppEventPanel` / `EditEntryPanel` — 日付非依存
- `handleBlockTap`(タイマー開始/停止) — 日付非依存で仕様どおり動作しており変更しない
- `WeekStrip` 自体(日表示専用) — 無改修。今回のヘッダーボタンとスタイルの考え方は共通化するが、
  レイアウト(グリッドのセル vs 独立した横並びリスト)が異なるため、コンポーネントとしての
  共通化(関数抽出等)は行わない。過度な抽象化を避け、クラス名の組み立てロジックが将来
  3箇所目で必要になった時点で共通化を検討する

## スコープ外

- 予定ブロック自体への編集ボタン(✎)の復活(P2-5時点の設計への回帰)。今回は
  `CalendarContextPanel` 方式を前提に、日付選択手段の欠落のみを埋める
- 日表示・週表示以外(月表示等)の追加 — 本アプリに月表示は存在せず対象外
- モバイルでのコンテキストパネルの自動オープン(現状、日表示でも `WeekStrip` で日付を
  切り替えた後は手動でパネルを開く操作が必要であり、この既存動作を踏襲する。週表示だけ
  自動オープンにする変更は行わない)

## テストシナリオ

対象ファイル: `tests/components/calendar-view-week-select.test.tsx`(新設)

- S1 [単体]: Given 週表示(`viewParam="week"`)・`dateParam`未指定(今日を表示中) When
  今日以外の曜日ヘッダーをクリック Then `router.push` が
  `/calendar?view=week&date=<その日のyyyy-MM-dd>` で呼ばれる
- S2 [単体]: Given 週表示・他の曜日を選択中(`dateParam`にその日を指定) When 今日の曜日ヘッダーを
  クリック Then `router.push` が `/calendar?view=week`(`date`パラメータなし)で呼ばれる
  (P8-1の「今日は`date`を付けない」不変条件の回帰確認)
- S3 [単体]: Given 週表示・`dateParam`で他の曜日(今日ではない日)を選択中 Then その曜日ヘッダーに
  `aria-pressed="true"` が付き、今日の曜日ヘッダーには `aria-current="date"` が付く
  (両者が異なる曜日であることを確認)
- S4 [単体]: Given 週表示・`dateParam`未指定(今日を選択中) Then 今日の曜日ヘッダーに
  `aria-pressed="true"` と `aria-current="date"` の両方が付く(選択中かつ今日の複合状態)
- S5 [結合]: Given 週表示・`dateParam`で今日ではない日(その日にアプリ内予定`source:"app"`が
  1件ある)を指定して描画 When その日の予定に対する `CalendarContextPanel` 内の編集ボタンを
  クリック Then `AppEventPanel` が編集モードで開き、正しいタイトル・時刻が初期値として渡る
- S6 [結合]: Given 週表示・`dateParam`で今日ではない日(その日に確定済み実績が1件ある)を指定して
  描画 When `CalendarContextPanel` 内のその実績の編集ボタンをクリック Then `EditEntryPanel` が
  開き、正しいタイトル・時刻が初期値として渡る
既存回帰確認(新規テストコードは書かず、実装後に既存スイートを実行して確認する):

- S8 [結合]: `tests/components/calendar-view.test.tsx` / `calendar-view-timer.test.tsx` /
  `calendar-view-overlay.test.tsx` / `calendar-view-edit.test.tsx` / `calendar-view-recurring.test.tsx` /
  `calendar-view-app-events.test.tsx` / `calendar-view-restart.test.tsx` が無改修で通過する
  (週表示ヘッダーの `<div>`→`<button>` 化がタイマー開始/停止・オーバーレイ描画・既存の日表示
  `WeekStrip` に影響しないことの確認)

**実装後の実測メモ**: S5/S6は、テストが`dateParam`で直接その日を指定して描画するため、
週ヘッダーのボタン化(S1〜S4の実装)より前から通過していた(すでにURLがその日を指していれば
`CalendarContextPanel`は正しく機能する設計だったため)。つまりバグの実体は「その日へ遷移する
手段がなかった」ことに限定されており、遷移後の編集ロジック自体には手を入れていない。
S5/S6は新規コードのRedテストではなく、S1〜S4で追加したナビゲーションが実際に編集可能な
状態へ到達することを保証する結合確認として位置づける。

### タイムゾーン(CLAUDE.md R-1 の遵守)
