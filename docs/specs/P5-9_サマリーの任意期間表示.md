## 目的

サマリー画面(`/summary`)は現在 `?range=today|week` の2択固定で、**基準日が常に「今日」**。
「昨日はどうだったか」「先月の見積もり精度は」を確認する手段が存在しない。
さらにデータ取得(`fetchSyncedEvents` / `fetchTimeEntries`)と定期予定の実体化
(`materializeRecurringInstances`)がいずれも `computeSyncRange` の「今週±1週間」固定のため、
UIだけ変えても過去のデータは取得できない。

プロダクトの核心価値「見積もりが当たるようになる」は、1日単位のズレではなく
**期間をまたいだ傾向**(例:「レビューはいつも予定を37%超える」)が見えて初めて効く。
本タスクはサマリーを任意期間に対応させ、その傾向を読めるようにする。

DBスキーマ変更なし。

## 仕様

### URL契約

`/summary?range=<key>&date=<YYYY-MM-DD>&from=<YYYY-MM-DD>&to=<YYYY-MM-DD>`

| `range` | 集計期間(半開区間 `[start, end)`) | 使うパラメータ |
|---|---|---|
| `today`(既定) | `[startOfDay(anchor), +1日)` | `date` |
| `week` | `[startOfWeek(anchor, 月曜始まり), +1週)` | `date` |
| `month` | `[startOfMonth(anchor), +1ヶ月)` | `date` |
| `custom` | `[startOfDay(from), startOfDay(to) + 1日)`(両端の日を含む) | `from`, `to` |

- `anchor` は `date` をローカル0時にパースしたもの。省略・不正時は「今日」
- `range` が未知の値のときは `today` として扱う
- `custom` で `from`/`to` がパース不能、または `to < from` のときは `today` へフォールバックする
- 日付のパース・整形は既存の `parseDateParam` / `toDateParam`(`lib/calendar/view-date.ts`)を再利用する

### 期間の上限

- 集計期間の日数は **最大366日**。367日以上を指定した場合は集計・データ取得を行わず、
  エラー文言「期間は最大366日までです」のみを表示する(期間選択UIは操作可能なまま残す)
- 上限判定は `custom` のみ発生しうる(today/week/month は最大31日)

### 期間選択UI

```
[ 今日 ][ 今週 ][ 今月 ][ カスタム ]

←  2026-08-01(金)  →              ← today/week/month のみ表示

--- カスタム選択時 ---
開始 [2026-07-01] 〜 終了 [2026-07-31]  [表示]
```

- タブは4つ。既存の `role="group"` + `aria-pressed` のパターンを踏襲する
- 前後移動(`←` / `→`)は `today` = ±1日、`week` = ±7日、`month` = ±1ヶ月。
  リンク先は `?range=<key>&date=<移動後>`。`custom` ではナビ行を表示しない
- 期間ラベル(既存 `calendar-view.tsx` と同じ `date-fns` + `ja` ロケール表記に揃える)
  - `today`: `2026年8月1日(土)`
  - `week`: `2026年7月27日〜8月2日`
  - `month`: `2026年8月`
  - `custom`: `2026年7月1日〜7月31日`(年をまたぐ場合は末尾も `2027年1月3日` と年を出す)
- カスタムのフォームは `<form method="get" action="/summary">` +
  `<input type="date" name="from" / name="to">` + hidden `range=custom`。
  Server Component のまま実装し `"use client"` は使わない
- フォームの初期値は現在の `from`/`to`(未指定時は今日)

### 集計

- 集計対象は **既存踏襲**:「開始時刻が期間内にあるもの」(P3-2 の仕様を変更しない)
- `computeGapSummary` は無改修。ヒーロー(合計・ズレ%)・件数ステータス行は現行のまま動く
- ヒーロー見出しは期間に応じて「今日のズレ / 今週のズレ / 今月のズレ / この期間のズレ」

### 予定ごとの内訳

- 期間が **1日(dayCount === 1)** のとき: 現行どおり1予定1行(開始遅延・ズレ%を表示)
- 期間が **2日以上** のとき: **同じタイトルで集約**した行を表示する
  - 表示項目: タイトル / 件数(`N件`)/ 計画合計・実績合計 / ズレ合計とズレ% / 平均開始遅延
  - `gapPercent` は合計値から再計算する(`planMinutes === 0` のときは `null` = 非表示)
  - 平均開始遅延は `startDelayMinutes` が非 null(=着手済み)の予定のみの平均を四捨五入。
    全件未着手なら非表示
  - 全件未着手のグループは現行と同じ「未着手」バッジを出す(ズレ・%は非表示)
  - 並び順: `|gapMinutes|` 降順 → タイトル昇順(安定)

### 割り込み・フリー作業

- 期間が2日以上のときは同様にタイトルで集約し、`タイトル / N件 / 合計時間` を表示する
- 1日のときは現行どおり1実績1行

### データ取得

- `fetchSyncedEventsInRange(client, range)` / `fetchTimeEntriesInRange(client, range)` を新設し、
  既存の `fetchSyncedEvents(client, baseDate)` / `fetchTimeEntries(client, baseDate)` は
  `computeSyncRange(baseDate)` を渡す薄いラッパにする(カレンダー・計測画面は無改修)
- `materializeRecurringInstances(client, baseDate, range?)` に第3引数を追加(省略時は現行どおり
  `computeSyncRange(baseDate)`)。サマリーは選択期間を渡し、その期間ぶんの定期予定を
  `synced_events` へ冪等 upsert する。upsert は既に冪等なため本体ロジックは無改修
- 実体化 → 取得の**直列**実行という現行の制約を維持する

### エラー時の挙動

- 期間上限超過: 集計を行わず「期間は最大366日までです」を表示(HTTPエラーにはしない)
- 不正な日付パラメータ: エラーにせず `today` へフォールバック(現行の `parseViewState` と同じ思想)
- 予定・実績の取得失敗: 現行どおり日本語メッセージの例外(「予定の読み込みに失敗しました」等)

## スコープ外

- 期間ごとの推移グラフ・チャート表示
- CSV/レポート出力(MVPスコープ外)
- 期間選択のプリセット保存・既定期間のユーザー設定
- 「重なった分だけ按分」する集計方式への変更(P3-2 の集計仕様は据え置き)
- カレンダー画面・計測画面の期間指定(本タスクはサマリーのみ)
