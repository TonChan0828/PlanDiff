## 目的

実績(`time_entries`)・予定(アプリ内予定)の開始/終了時刻を編集する際、モバイル(タッチ操作)での
時刻修正のしづらさを解消する。

### 原因

`components/date-time-stepper.tsx`(`DateTimeStepper`)は、`EditEntryPanel`(実績修正)・
`EditStartPanel`(実行中タイマーの開始時刻修正)・`AppEventPanel`(予定作成/編集)の3箇所すべてで
使われている、年/月/日/時/分の5セグメント入力コンポーネント。P5-6でPCの物理キーボード
(← → で桁移動、↑ ↓ で増減、数字キーで直接入力し自動送り)を前提に設計された。

値を表示する各セグメントの `<input>` は `readOnly`(266〜295行目)のため、**モバイルでは仮想
キーボードが表示されず、数字入力による直接編集ができない**。残る手段は共有の▲▼ボタン
(300〜320行目、フォーカス中セグメントに±1ずつ作用)のタップのみで、例えば分を`:00`から`:47`に
変えるには▼ボタンを47回タップする必要がある。PC/モバイルでの分岐は現状どこにも存在しない。

## 仕様

### 方針(plan modeでユーザー承認済み)

モバイルでは `<input type="datetime-local">` に切り替え、OS標準のホイールピッカー(iOS Safari /
Android Chromeとも日時をひとつのタップ操作でまとめて選択できるネイティブUI)に任せる。PC版は
現行の `DateTimeStepper`(セグメント入力)を維持する(P5-6でPCのTAB操作性改善のために設計された
ものであり、物理キーボードがある環境では現行UIの方が優れているため)。

`DateTimeStepper` の `value`/`onChange` 契約は既に `LOCAL_DATE_TIME_FORMAT`
(`lib/ui/local-date-time.ts` の `"yyyy-MM-dd'T'HH:mm"`)というローカル文字列であり、これは
`<input type="datetime-local">` のvalue形式と完全に一致する。そのため呼び出し元3コンポーネント
(`EditEntryPanel` / `EditStartPanel` / `AppEventPanel`)は無改修とする。

### 1. 共有フックの新設: `lib/ui/use-is-desktop.ts`

`components/calendar-context-panel.tsx`(17〜40行目)にある以下のロジックを移設する
(挙動不変のリファクタ。ロジックそのものは変更しない):

- `DESKTOP_QUERY = "(min-width: 1024px)"`
- `getDesktopMedia()`(`window.matchMedia` の呼び出しをモジュールスコープでキャッシュ。
  `useSyncExternalStore` の `getSnapshot` が毎レンダー呼ばれても作り直さないため。P6-3由来)
- `subscribeDesktop(callback)`
- `getDesktopSnapshot()`

これらをexportせず、`useIsDesktop(): boolean` という1つのフックとしてまとめてexportする:

```ts
export function useIsDesktop(): boolean {
  return useSyncExternalStore(subscribeDesktop, getDesktopSnapshot, () => false);
}
```

`getServerSnapshot` は既存の `calendar-context-panel.tsx` と同じ `() => false`(SSR・ハイドレーション
直後は常にモバイル扱い)を踏襲する。これによりデスクトップでも初回描画は一瞬モバイル版
(ネイティブ`datetime-local`)になり、クライアントでの`matchMedia`評価後にセグメント入力へ
切り替わる。これは`calendar-context-panel.tsx`が既に同じパターンで持っている挙動であり、
本対応で新たに導入するリスクではない。

`calendar-context-panel.tsx` は独自定義を削除し、このフックを import して
`const desktop = useIsDesktop();` に置き換える(モジュールスコープの`desktopMedia`キャッシュ変数は
フック側に1つだけ存在する状態になる)。

### 2. `components/date-time-stepper.tsx` の分岐

`DateTimeStepper` の描画本体を `useIsDesktop()` の値で分岐する。

- **`isDesktop === true`**: 現行のセグメント入力(`role="group"`配下の5つの`spinbutton`+共有▲▼+
  カレンダーボタン+隠しdate入力)をそのまま描画。コード・挙動とも無変更。
- **`isDesktop === false`**: 単一のネイティブ入力を描画する。

```tsx
<div className="flex flex-col gap-1 text-sm">
  <label className="text-sm" htmlFor={inputId}>{label}</label>
  <input
    id={inputId}
    type="datetime-local"
    value={value}
    onChange={(event) => onChange(event.target.value)}
    disabled={disabled}
    className="border-line bg-surface min-h-11 rounded-lg border px-3 text-sm disabled:opacity-50"
  />
</div>
```

- `value` は変換せずそのまま渡す(空文字 `""` も含め、`LOCAL_DATE_TIME_FORMAT` 文字列は
  `datetime-local` のvalue仕様と互換)。
- `onChange` はネイティブ入力の生値をそのまま `onChange(next)` に渡す(セグメント版のような
  `setLocalSegment`/`stepLocalSegment` 経由の変換は行わない)。
- `label` は `<label htmlFor>` で関連付ける(セグメント版の `aria-label` 個別付与とは異なり、
  ネイティブ入力は1つの `<label>` で十分)。`inputId` は `useId()` で生成する。
- `disabled` prop をそのままネイティブ入力の `disabled` に渡す。**現行の `timeDisabled`
  (`disabled || !value` で空値時も自動的に無効化する)ロジックはモバイル版には適用しない**
  ("仕様(補足)"参照)。
- ▲▼ボタン・カレンダーボタン・隠しdate入力は描画しない(ネイティブUIが代替するため)。

### 3. 仕様(補足): 空値の扱い

現行のセグメント版は値が空文字のとき `timeDisabled = true` とし、セグメント・▲▼を強制的に
無効化してユーザーが数値を入れられないようにしている(空のまま桁だけ入力される事故を防ぐため、
と推測される)。

ネイティブ `datetime-local` は空値でも問題なく描画され、タップすればピッカーが開いて選択できる。
調査の結果、3つの呼び出し元(`EditEntryPanel` / `EditStartPanel` / `AppEventPanel`)はいずれも
`useState` の初期値を常に既存の日時から生成しており、**空文字で `DateTimeStepper` に値を渡す
実運用上のケースは存在しない**。そのためモバイル版では空値の特別扱い(自動disabled化)を行わず、
`disabled` propのみを尊重する。既存のセグメント版の空値挙動(S27/S28)はデスクトップ分岐のみに
残るため無改修。

### 4. 影響を受けないコード

- `EditEntryPanel` / `EditStartPanel` / `AppEventPanel`: props契約(`label`/`value`/`onChange`/
  `disabled`)が不変のため無改修。
- `components/recurring-rule-panel.tsx` の `<input type="time">`: 元々`DateTimeStepper`を使って
  おらずP5-5/P5-6のスコープ外だった。本対応でも対象外。

## スコープ外

- モバイル専用のカスタムドラムピッカー等、ネイティブ入力以外の新規UI実装(plan modeでユーザーが
  不採用と判断)
- タイムライン上のオーバーレイブロックへのドラッグ/スワイプによる直接時刻変更(別要望が出た場合に
  改めて検討)
- `recurring-rule-panel.tsx` の `<input type="time">` の見直し
- 1024px境界の変更・新設(既存の`calendar-context-panel.tsx`と同じ`min-width: 1024px`を踏襲)
