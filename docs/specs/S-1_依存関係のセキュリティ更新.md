## 目的

`npm audit` が報告する **high 7件** を解消し、以後の再発を CI で検知できるようにする。
アプリの振る舞いは一切変えない(機能追加・UI変更・DB変更なし)。

本番は Vercel(https://plandiff.vercel.app)で公開済みであり、後述のとおり
**本リポジトリの実コードに該当する攻撃経路がある** Advisory が含まれるため、放置は実リスク。

## 仕様

### 更新内容

7件すべてが**推移依存**であり、直接依存は `next` のみ。`package.json` の変更は2行だけで、
残りは lockfile の再解決で解消する。

| 脆弱パッケージ | 現在 | 依存元 | 更新後 | 手段 |
|---|---|---|---|---|
| `next` | 16.2.10 | 直接依存(ピン留め) | 16.3.3 | `package.json` を書き換え |
| `eslint-config-next` | 16.2.10 | 直接依存(ピン留め) | 16.3.3 | `next` とバージョンを揃える(既存方針) |
| `sharp` | 0.34.5 | `next` の optionalDependencies(`^0.34.5`) | 0.35.3 | next 16.3.3 が `^0.35.3` を要求するため自動解決 |
| `postcss`(next 配下) | 8.4.31 | `next` が固定 | 8.5.23 | 同上(next 16.3.3 が 8.5.23 を固定) |
| `postcss`(トップレベル) | 8.5.16 | `@tailwindcss/postcss`(`^8.5.15`)/ `vite`(`^8.5.16`) | 8.5.26 | 範囲内 → `npm update` |
| `nanoid` | 3.3.15 | `postcss@8.5.26`(`^3.3.17`) | 3.3.18 | 範囲内 → `npm update` |
| `undici` | 7.28.0 | `jsdom@29.1.1`(`^7.25.0`) | 7.29.0 | 範囲内 → `npm update` |

- **`npm audit fix --force` は使わない**。何が変わるか制御できないため、上記の明示的な指定で行う
- `next` / `eslint-config-next` は既存の書式どおり**キャレットなしのピン留め**を維持する
  (`npm install ... --save-exact`)

### CI への監査ステップ追加

`.github/workflows/ci.yml` の `npm ci` 直後に以下を追加する。

```yaml
      - run: npm audit --audit-level=high
```

`npm ci` の後・`format:check` の前に置く(依存の問題を最速で落とすため)。
これにより、以後 high 以上の Advisory が公開された時点で PR が落ち、気づける。

**副作用として認識しておくこと**: 無関係な PR が新規 Advisory の公開で落ちることがある。
その場合は「その PR で直す」のではなく、本仕様書と同じ手順で別途更新タスクを立てる。

### 16.2.10 → 16.3.3 の非互換確認(リリースノートより)

| 変更 | 本リポジトリへの影響 |
|---|---|
| TypeScript `compilerOptions` の非推奨サポート削除(`baseUrl` / `node10 moduleResolution` / `downlevelIteration`) | **影響なし**。`tsconfig.json` は `baseUrl` を使わず `paths` のみ、`moduleResolution: "bundler"` |
| Node streams が SSR の既定に | 振る舞い変化の可能性あり。build と 375px 表示確認で見る(S6) |
| Edge runtime の非推奨化(self-contained runtime へ改名) | **影響なし**。edge runtime は未使用 |
| `experimental.viewTransition` / `experimental.dynamicIO` / `experimental.useCache` の非推奨・削除 | **影響なし**。`next.config.ts` は `experimental.optimizePackageImports` のみ |
| `eslint-config-next` の新ルール | `npm run lint` で新規エラーが出る可能性あり。**出たらルールを無効化せずコードを直す** |

### lockfile について

再解決により各プラットフォーム向けの optional バイナリ(`lightningcss-*` /
`@tailwindcss/oxide-*` / `@unrs/resolver-binding-*` / `@rolldown/binding-*` 等)が
追加され、`package-lock.json` の diff が大きくなる見込み。これは異常ではない
(現状の lockfile は一部プラットフォームのエントリしか持っていない)。
**クリーンな `npm ci` が通ることをもって正とする**(S5)。

## 実施結果と、仕様策定時の想定との差分(2026-08-26 実測)

### 1. `next` 更新後に**新たに2件**の high が浮上した(計9件を解消)

`eslint-config-next` 16.3.3 が ESLint ツールチェーンを更新した結果、更新前には
ツリーに存在しなかった以下が現れた。いずれも**範囲内に修正版があり**、同じ方針で解消した。

| パッケージ | 依存元 | 更新 | Advisory |
|---|---|---|---|
| `brace-expansion` | `eslint@9` → `minimatch@3.1.5`(`^1.1.7`) | 1.1.15 → **1.1.18** | GHSA-3jxr-9vmj-r5cp / GHSA-mh99-v99m-4gvg / GHSA-rgw5-rvv9-x895(DoS) |
| `brace-expansion` | `eslint-config-next` → `typescript-eslint` → `minimatch@10.2.5`(`^5.0.5`) | 5.0.7 → **5.0.9** | 同上 |
| `js-yaml` | `eslint@9` → `@eslint/eslintrc@3.3.5`(`^4.1.1`) | 4.3.0 → **4.3.1** | GHSA-5p4m-2wfm-xmqj(!!omap の二次的CPU消費) |

`brace-expansion` は **1.1.18 と 5.0.9 の2本がツリーに残るのが正しい**。
`minimatch@3` が `^1.1.7`、`minimatch@10` が `^5.0.5` を要求しており、semver 上1本に
寄せられない。`overrides` で強制的に1本化すると、いずれかの `minimatch` が壊れる。

### 2. `postcss` は 8.5.26 ではなく **8.5.23 に dedupe** された

`next@16.3.3` が `postcss` を 8.5.23 で*厳密固定*しており、それが `@tailwindcss/postcss`
(`^8.5.15`)と `vite`(`^8.5.16`)の要求も満たすため、npm がコピーを1本に畳んだ。
脆弱範囲は `<=8.5.22` なので 8.5.23 で解消済み。当初想定より良い状態
(**ツリー内の postcss が1本だけ**)。`nanoid` も 3.3.18 に更新済み。

### 3. `AGENTS.md` が Next.js により再生成された

`next dev` 実行時に `Generated AGENTS.md for AI agents` が出力され、`AGENTS.md` が更新された。
このファイルは**全体が `<!-- BEGIN:nextjs-agent-rules -->` ブロック**であり、
16.3.3 が文言を更新したもの。ユーザー記述の消失はない。生成元は
`node_modules/next/dist/server/lib/generate-agent-files.js` で、再生成される性質のため
**S-1 のコミットに含める**(生成された文言自身がそう指示している)。
`npm run format:check` は通ることを確認済み。

## スコープ外

- `jsdom` の major 更新(29 → 30)。`jsdom@29.1.1` の `undici: ^7.25.0` の範囲内に
  修正版 7.29.0 があるため不要。major 更新はテスト環境の挙動変化リスクだけを増やす
- `@tailwindcss/postcss` 4.3.2 → 4.3.3 など、脆弱性と無関係なバージョン追随
- `moderate` / `low` の Advisory への対応(現時点で0件。CI の閾値も `high` に置く)
- Dependabot / Renovate の導入(継続的な自動 PR。必要なら別タスクで検討する)
- アプリコード・DB スキーマ・環境変数の変更(いずれも本件では発生しない)

## テストシナリオ

本件は**新しい振る舞いを追加しない**変更であるため、新規のテストコードは書かない。
代わりに、既存の回帰スイート全件と監査結果・クリーンインストール・表示確認で
「壊れていないこと」を担保する。**この点はユーザー承認を要する判断**として明記する。

- S1 [結合]: Given 更新後の依存ツリー / When `npm audit --audit-level=high` を実行 /
  Then 終了コード0(high 以上が0件)
- S2 [単体]: Given 更新後のツリー / When `npm run check`(typecheck → lint → 単体・
  コンポーネントテスト → build)/ Then 全ステップ合格・テストは既存件数から**減っていない**
- S3 [結合]: Given ローカル Supabase 起動済み / When `npm run test:integration` /
  Then 結合テスト全件合格(Route Handler / Server Action〜DB・RLS を跨ぐ流れが健全)
- S4 [単体]: Given 更新後のツリー / When `TZ=UTC` および `TZ=Pacific/Kiritimati` で
  単体テストを実行 / Then 全件合格(バグ由来ルール R-1)
- S5 [結合]: Given `node_modules` を削除した状態 / When `npm ci` /
  Then 成功する(lockfile と `package.json` が整合している)
- S6 [結合]: Given 更新後のアプリを `npm run dev` で起動 / When 375×667 で
  `/`(LP)・`/calendar`・`/summary`・`/settings` をライト/ダーク両方で開く /
  Then 横スクロール0px、オーバーレイ・グラフの描画崩れなし
  (16.3.0 の SSR 既定変更の影響が出るとすればここ)
- S7 [結合]: Given 更新後の `.github/workflows/ci.yml` / When PR を出す /
  Then `npm audit --audit-level=high` を含む全ステップが緑になる

### 異常系・境界値の扱い

- **異常系**: S1 の裏返し(high が残っていれば失敗する)、S5(lockfile 不整合なら `npm ci` が失敗する)、
  S2 の lint(新ルール違反があれば失敗する)が異常系の検出役を担う
- **境界値**: `--audit-level=high` の閾値そのものが境界。`moderate` を落とさず `high` で落とす
- **既存テストの網羅性に依拠する**ため、テストの skip / コメントアウト / 除外による
  件数減少は禁止(CLAUDE.md 完了の定義3)。件数を before/after で突き合わせる
