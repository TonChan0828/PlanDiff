# 仕様書: 検証と運用の改善

- ステータス: 承認済み(2026-09-30。ユーザーの「列挙した内容を…並列して実施」による承認)
- 関連: 調査で列挙したテスト・本番設定・エラー監視の改善、CLAUDE.md R-1

## 目的
主要操作の回帰をCIで検出し、時刻による偶発的な失敗をなくす。ブラウザとサーバーのエラーをVercelログで照合できるようにする。

## 仕様
- 結合テストとE2EはローカルSupabaseを使い、CIの独立ジョブで実行する。既存checkジョブと並列にする。
- E2Eで375pxのカレンダー予定編集・実績編集・削除確認・日またぎ予定・タイマー・サマリーを実ブラウザ検証する。テストユーザーはテスト専用ローカルDBに作成し終了時に削除する。
- 既知の時刻依存テスト3ファイルはモジュール評価前に時計を正午へ固定する。UTC/UTC+14でも検証する。
- instrumentation.tsでサーバーの未捕捉エラーを構造化ログへ記録する。instrumentation-client.tsとエラー境界は同一オリジンの監視APIへ報告する。
- ログにはイベント種別・発生箇所・既知のページパス・標準エラー名・Next digestだけを含め、メッセージ/stack/query/cookie/メール/ユーザーIDは含めない。
- 監視の通信失敗は画面動作へ影響させない。報告重複・件数・payloadのサイズを制限する。
- 本番設定を読み取りで確認し、確認日時と未確認項目を運用手順に記録する。認証情報や環境変数値は記録しない。

## スコープ外
本番へのデプロイ、production DBへのmigration適用、外部監視サービス契約。実機OSの通知許可・Push到達にはユーザーの端末が必要で、実施できなかった場合は明記する。

## テストシナリオ
- O1 [単体]: エラーに秘密情報が含まれても監視payloadには標準名・digest以外を含めない。
- O2 [単体]: クエリ付きURLや不明なパスはログへそのまま記録しない。
- O3 [単体]: 同じブラウザエラーを重複送信せず、通信失敗は例外を出さない。
- O4 [結合]: 同一オリジンの有効な報告だけを監視APIが受け取り、構造化ログを記録する。
- O5 [結合]: 不正payload/別オリジン/件数上限は拒否し、ログに任意文字列を出さない。
- O5a [結合]: Content-Lengthがなくても本文サイズを読み取り中に制限し、上限超過時はstreamを打ち切る。
- O6 [結合]: サーバーinstrumentationが発生箇所とdigestを記録し、requestの秘密情報を記録しない。
- O7 [E2E]: 375pxで詳細パネルから予定・実績の編集ダイアログを開き、最前面で操作できる。
- O8 [E2E]: 削除確認のTab/Shift+Tabがダイアログ内に留まり、Escapeで閉じる。
- O9 [E2E]: 日またぎ予定を翌日の詳細一覧から編集できる。
- O10 [E2E]: フリータイマーの開始・停止が画面とDBに反映され、サマリーへ移動できる。
- O11 [単体]: 既知時刻依存テスト3ファイルが固定時計でUTC/UTC+14双方で通過する。


## 検証記録

- `npm run check`: 型チェック・lint・unit 140ファイル901件・production buildまで成功。`npm run format:check`と`git diff --check`も合格。
- UTC/UTC+14の指定3ファイルは55件ずつ合格。Playwrightは4ケースを検出。ブラウザ実行とSupabase統合テストはDocker daemon未起動のため未実施。
- O11: `calendar-view-restart`、`calendar-view-timer`、`summary/page-charts`の計26件が、ローカル正午へ時計を固定した後にUTC/UTC+14双方で合格。
- `supabase/config.toml`の現行CLIで無効な`local_smtp`を公式設定の`inbucket`へ変更。CLIは設定を読めたが、Docker daemon不在でサービス状態を確認できなかった。
- Vercel Productionの環境変数は名前と適用環境のみ確認し、値は読み出していない。Cron定義は`0 22 * * *`。Supabase Productionの状態は未確認。
- `npm audit`は元lockfileと同じ4 moderate / 5 high / 1 criticalを返した。High以上のため既存CI監査は失敗し、P16依存変更が原因でないことを確認。別作業S-2をPhase 14に起票した。Next.js advisory GHSA-vcvr-r3jv-pc5jに関して、`next/og`は静的アイコン生成に限られ、リクエスト由来の文字列をSVGへ渡していない。
