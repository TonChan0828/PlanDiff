# 仕様書: G-91 タイマーの止め忘れ対策(アプリ内の警告と、終了時刻の修正候補)

- ステータス: 承認済み(2026-11-27)
- 関連: GitHub Issue #91 / [P13-1](P13-1_計測しっぱなしの検知とPush通知.md) / [G-98](G-98_実績編集の予定との差分表示.md) / [G-104](G-104_週表示の長時間実績の省略表示.md)
- 指示資料: なし(2026-11-27 に確認。README のみ)

## 目的

止め忘れた実績は集計を大きく歪める。12時間後の Push 通知(P13-1)は、通知が無効な端末には届かず、気づくのも遅い。アプリを開いたときに気づけて、直しやすくする。

## 現況

- 実行中の表示: カレンダーの `RunningTimerBar`、計測画面の `RunningTimerHero`。経過時間だけで、警告はない
- 完了した実績が不自然に長くても、目印も修正の手がかりもない

## 仕様

### 判定(純粋関数 `lib/timer/forgotten.ts`)

- **長時間**: 経過(実行中は現在まで、完了は終了まで)が **6時間以上**(閾値は定数。承認時に6時間で確定)
- **予定超過**: 予定に紐づく実行中タイマーで、予定の終了から **15分以上**過ぎている(直後の少しの超過で毎回警告しない)

### 1. 実行中の警告(カレンダーのバーと計測画面のヒーロー)

- 長時間: 「6時間以上計測しています。止め忘れではありませんか?」
- 予定超過: 「予定の終了(10:00)を過ぎて計測しています」。両方に当たる場合は両方出す
- 経過に合わせて自動で出る。`role="status"`。色だけに頼らずアイコンと文言で示す。停止の操作は変えない(自動停止はしない。P13-1 の決定を維持)
- 計測画面で予定が読み込み範囲外の場合、予定超過は出さず、長時間の警告だけを出す

### 2. 完了した実績の目印と修正候補

- 実績の編集パネルで、長時間の実績には「止め忘れの可能性があります(6時間以上)」を表示する
- 長時間の実績が予定に紐づき、**予定の終了が実績の開始より後で、実績の終了より前**の場合は、「終了を予定の終了(10:00)にする」ボタンを出す
  - 押すと終了の入力欄だけが変わる。**自動では保存しない**(保存ボタンを押すまで確定しない)。G-98 のズレの欄もその場で更新される
  - 条件に合わない(フリー実績、予定がない)場合は、目印だけで候補は出さない(推測の時刻は提示しない)
- 右パネル「この日」の実績一覧で、長時間の実績に「止め忘れの可能性」の文字の目印を付ける

## スコープ外

- 自動停止・自動修正、閾値の設定画面、Push 通知(P13-1)の変更、実行中タイマーを過去の時刻で停止する操作、サマリーでの目印

## テストシナリオ

現在時刻は `setSystemTime` で固定し、日時はローカルTZで組み立てる(R-1。現在時刻で結果が変わるため、通る既存テストの固定も確認する)。

- I1 [単体・境界]: 経過が閾値の1分前は長時間でない、ちょうどは長時間
- I2 [単体・境界]: 予定の終了から14分は超過でない、15分は超過。紐づきがない・予定がないと超過でない
- I3 [単体]: 候補の条件(開始 < 予定の終了 < 実績の終了)。予定の終了が開始以前・実績の終了以降なら候補なし
- I4 [画面]: 実行中の警告がバーとヒーローに出る。時間が進むと現れる。停止ボタンは変わらない
- I5 [画面]: 編集パネルの目印と候補ボタン。押すと終了の入力とズレの欄が変わり、保存するまで Server Action は呼ばれない
- I6 [画面]: フリー実績は目印だけ。短い実績には何も出ない
- I7 [画面]: 「この日」の一覧の目印
- I8 [UI]: 375px で、実行中バー・編集パネルが崩れず操作できる(R-2)
