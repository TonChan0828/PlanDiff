- 指示資料: なし(`docs/指示資料/` に本件に関する資料なし。2026-08-11 確認)

## 目的

`/track` を開いたまま深夜0時を過ぎても、「今日」の実績グループ・「今の予定から開始」の候補・
進行中バッジが古い日付基準のまま止まる不具合を解消する。

### 原因

`components/track-view.tsx` の `now` はローカル定義の `useHydrated`(`useSyncExternalStore` の
空購読版。ハイドレーション完了判定専用)を使い、ハイドレーション完了時点で1回だけ
`new Date()` を評価している(69-70行)。それ以降 `now` を更新するトリガーが存在しないため、
画面を開いたまま日付が変わっても以下がすべて古い日付のまま固定される。

- `groupEntriesByDay(timeEntries, now)`(`lib/track/entry-groups.ts`)の「今日」判定・
  未来日除外。**`now` が前日のまま止まっていると、実際は当日になった実績が
  「未来日」として除外される**(`day.getTime() > today.getTime()` で弾かれる)
- `selectQuickStartEvents(events, now)`(`lib/track/quick-start.ts`)の「進行中」判定・
  「当日これから始まる予定」の絞り込み(`isSameDay(start, now)`)
- 画面内の `isOngoing` バッジ(269-297行)

これは P8-1 で発見・修正した `CalendarView` と同じ原因(時刻の再レンダートリガー不在)であり、
`lib/time/use-now-minute.ts`(P8-1 で新設した分単位の共有ストア)を流用して解消する。

### P8-1 との違い(refresh 不要)

`CalendarView` は URL の `dateParam` に応じてサーバーから**表示週±1週間**のデータを取得するため、
日付が変わったら再取得が必要だった。一方 `/track` は `dateParam` を持たず、サーバーは常に
`computeSyncRange(new Date())` = **基準週の前後1週間、計3週間分**(`lib/google/sync-range.ts`)を
取得している。日付が1日進んだ程度ではこの範囲を外れないため、**`router.refresh()` は不要**。
クライアント側の `now` を更新するだけで、既に受け取っている props の中から正しく絞り込める。

## 仕様

### `components/track-view.tsx` の変更

- ローカル定義の `useHydrated` と `emptySubscribe`(45-52行)を削除する
- `now` の算出を `lib/time/use-now-minute.ts` の `useNowMinuteMs()` に置き換える

```ts
const nowMinuteMs = useNowMinuteMs();
const now = useMemo(
  () => (nowMinuteMs === null ? null : new Date(nowMinuteMs)),
  [nowMinuteMs],
);
```

- `hydrated` を参照していた箇所(320行の空状態表示ガード)は `now !== null` に置き換える
- それ以外のロジック(`quickStartEvents` / `entryGroups` の算出、`isOngoing` バッジ)は
  `now` を経由して自動的に追従するため変更不要

### 影響を受ける既存の表示(いずれも `now` 経由で自動的に追従する)

- 実績リストの日付見出し(「今日」/`M/d(E)`)と、日付またぎで当日実績が除外されない
- 「今の予定から開始」の進行中/当日これから始まる候補
- 進行中予定の「進行中」バッジ

## スコープ外

- `/summary` の日付またぎ+TZ非対称の是正(P8-3。サーバーTZ評価との非対称性の是正が
  セットで必要なため別項目)
- データ取得範囲(3週間)自体の見直し。今回は「範囲外に出ない」ことを前提にしており、
  範囲外に出る操作(遠い過去日への遷移等)は `/track` には存在しない

## テストシナリオ

### `TrackView`(`tests/components/track-view.test.tsx`)

- S18 [結合]: Given `/track` を開いたまま 23:59:30 を表示 When 00:00 まで時間を進める Then
  それまで「未来日」として除外されていた新しい当日分の実績が「今日」グループに現れる
  (`day.getTime() > today.getTime()` による誤除外が解消されることの回帰確認)
- S19 [結合]: Given 前日23:59に登録された予定(当日にまたがる)を表示 When 0時をまたぐ Then
  「今の予定から開始」の当日候補が新しい「今日」基準で再計算される
  (旧日基準では対象外だった当日の予定が候補に入る)
- S20 [結合]: Given 進行中予定を表示中に0時をまたぐ Then 「進行中」バッジの表示が
  新しい `now` を基準に再評価される(該当予定が範囲外にならないことを確認)

### タイムゾーン(CLAUDE.md R-1 の遵守)

- テストの日時はローカルTZで構築する(`new Date(2026, 7, 11, 23, 59)` 形式)
- 基準時刻は `vi.useFakeTimers()` + `vi.setSystemTime()` で固定する
  (既存の `tests/components/track-view.test.tsx` の「正午基準」パターンを踏襲)
- コミット前に `TZ=UTC` と `TZ=Pacific/Kiritimati`(UTC+14)で対象ファイルを実行する

## 検証(手動)

- OSのシステム時刻を 23:59 にして `/track` を開き放置 → 00:00 で「今の予定から開始」・
  実績リストの「今日」グループが新しい当日基準に切り替わることを確認する
- 375px 幅(ライト/ダーク)で表示崩れがないこと(ロジック変更のみのため大きな崩れは想定しないが、
  テキスト更新のタイミングで折り返しが変わらないか確認する)
